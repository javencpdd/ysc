# 部署到另一套 M20（GOS 主机）

> 目标：在**第二台 M20 Pro** 的 GOS 主机上，把 `m20-ai-detect`（采样器）+ `m20-ai-console`（Web 控制台）
> 完整装起来并验证通过。全程约 20 分钟，可重复执行（幂等）。
>
> 本文所有结论都对应仓库里的实际脚本：`deploy/preflight.sh`、`deploy/install.sh`、
> `deploy/install-local.sh`、`deploy/bootstrap.sh`、`deploy/console-bootstrap.sh`。改脚本请同步改本文。

---

## 总览（先看这一张表）

| 步骤 | 做什么 | 命令 | 在哪台机器 | 章节 |
|---|---|---|---|---|
| ⓿ 体检 | 只读检查"能不能装、装哪" | `bash deploy/preflight.sh --base <候选>` | 目标机 | §0.5 |
| ① 选路径 | 定 BASE（含 `src/m20_ai_detect` 的那层） | `ls <候选>/src/m20_ai_detect/__init__.py` | 目标机 | §1.0 |
| ② 部署 | A 推送 **或** B 就地，二选一 | A：`install.sh user@<IP>`　B：`install-local.sh --from` | A=开发机、B=目标机 | §4 / §10 |
| ③ 初次引导 | 依赖、目录、unit、logrotate、doctor | `bootstrap.sh` → `console-bootstrap.sh` | 目标机 | §4.2 / §4.3 |
| ④ 验收 | doctor 全绿 + 能出图 + 采集能落盘 | 见验收清单 | 目标机 | §5 |
| ⑤ 回滚 | 从 `.backup/` 恢复 | `tar xzf .backup/code-<TS>.tar.gz` | 目标机 | §7 |

**四种典型场景，直接对号入座：**

| 场景 | 走哪几节 | 关键命令 |
|---|---|---|
| **新机器首次装机（有网、能 SSH）** | §0 → §0.5 → §1 → §4 → §5 | `preflight` → `install.sh` → `bootstrap.sh` → `console-bootstrap.sh` |
| **已有机器升级代码** | §7（回滚预案）→ §4.1 或 §10.1 | `install.sh user@<IP>` 或 `install-local.sh` |
| **现场离线、只有 U 盘/文件夹** | §0.5（`--skip-network`）→ §1.0 情形②→ §10 | `preflight --skip-network` → `install-local.sh --from <dir>` |
| **只是换一台机器、路径也不变** | §0.5 → §3（改 6 项 env）→ §4.1 | 改 `SRC_F/B`、`AI_BASE` 后推送 |

## 0. 先决条件（先确认，别急着拷代码）

| 项 | 要求 | 怎么确认 |
|---|---|---|
| 目标主机 | 新 M20 的 **GOS** 主机（Ubuntu 20.04，账户 `user`） | `ssh <新别名> 'id -un; lsb_release -ds'` |
| SSH | 免密可达（BatchMode 能通） | `ssh -o BatchMode=yes <新别名> echo ok` |
| Python | ≥ 3.6（**零第三方依赖**，标准库即可） | `python3 --version` |
| ffmpeg | 已安装（抓帧/抽帧全靠它） | `ffmpeg -version \| head -1` |
| 相机源 | GOS 能直连本机 AOS 的 MediaMTX（`rtsp://<AOS内网IP>:8554/video1/2`） | `ffmpeg -rtsp_transport tcp -i <src> -frames:v 1 -f null -` |
| AI 服务 | 能访问 `M20AI_AI_BASE`（默认外网域名） | `curl -m 6 -o /dev/null -w '%{http_code}\n' <AI_BASE>` |
| 出网 | GOS 无公网时，需 AOS 做转发（见 ADR-003） | 在 GOS 上 `curl` 上面那个地址 |
| 磁盘 | 至少 5 GB 可用（raw/ + results/ + saved/） | `df -h /home` |

⚠️ **GOS 是唯一有 GPU/NPU 旁路与相机内网的主机**；NOS/AOS 不是默认部署位（ADR-001）。
新机器若三主机网段与当前不同，`10.21.31.x` 全部要按新机器改。

## 0.5 先跑一次预检查（决定"能不能装、装哪"）

**在目标机上跑，只读，不改任何文件**（放在 `deploy/preflight.sh`）：

```bash
# 候选路径：推荐先在候选目录上跑，看路径是否合适
bash deploy/preflight.sh --base ~/m20-ai-detect

# 离线现场（没有外网/相机还没上电）：跳过连通性检查
bash deploy/preflight.sh --base ~/m20-ai-detect --skip-network

# 严格模式：WARN 也算不通过（CI / 交付验收用）
bash deploy/preflight.sh --base ~/m20-ai-detect --strict
```

它检查 7 组、约 20 项，输出 `PASS / WARN / FAIL`，**退出码 0 = 可以装，1 = 先修**：

| 组 | 检查内容 | 典型 FAIL |
|---|---|---|
| 1 系统账户 | 账户是否 `user`、OS 版本、架构 | — |
| 2 运行时 | `python3 ≥3.6`、`ffmpeg` | 缺 ffmpeg（抽帧/抓帧全靠它） |
| 3 资源 | 磁盘可用 ≥5 GB、可用内存 | 磁盘 <1 GB |
| 4 目标路径 | 是否空/已是本工程、可写、文件系统类型、位置、与 unit 是否一致 | 目录不可写、在 `/root`、NFS/vfat |
| 5 冲突 | 是否已装服务/在跑、5050 端口占用、helper 与 sudoers | — |
| 6 网络 | 相机 RTSP 能否取到 1 帧、DNS、AI 服务 HTTP | 相机取不到帧、AI 不可达 |
| 7 提权 | helper 白名单是否免密可用 | — |

示例结论：

```
  PASS 19 ｜ WARN 1 ｜ FAIL 0
  ✓ 可以部署。
```

> 别跳过这一步：`FAIL` 项（比如 ffmpeg 缺失、相机源不可达、路径不可写）在部署后才会以
> "服务 active 但采集无数据"的形式暴露，排查成本高得多。

**还没把代码拷到机器上？** 用开发机侧的远程体检（不需要目标机上有本项目）：

```bash
./deploy/install.sh user@192.168.0.196 --check
# 输出：host/user/os/python/ffmpeg/磁盘/内存/服务状态/项目目录/5050 监听数
# 只读，不传文件、不重启；连通性/主机名/公钥问题会给出分类提示
```


## 1. 复制什么、放哪里（路径要求）

### 1.0 三种情形：空目录 / 复制后自身 / 沿用现有

先明确一件事：**BASE（工作空间）= 含有 `src/m20_ai_detect/` 和 `m20-ai-detect.env` 的那一层目录**。
判断方法一条命令：

```bash
ls <候选目录>/src/m20_ai_detect/__init__.py   # 存在 → 这个目录就是 BASE
```

| 情形 | 该选哪个目录 | 说明 |
|---|---|---|
| **① 机器上还没有项目**（首次装机） | **选一个空目录**，如 `/home/user/m20-ai-detect` | `install.sh` 会 `mkdir -p` 自动创建；空目录最干净，不会与别人混放 |
| **② 已经把文件夹拷过去了** | **拷到的那一层就是 BASE**，直接用 | 关键：别多套一层。拷成 `/home/user/m20-ai-detect/` → BASE 就是它；若拷成 `/home/user/辅助工具/m20-ai-detect/`，BASE 是**后面那层**，不是 `辅助工具/` |
| **③ 升级已有部署** | 沿用现有 BASE（别换） | 查法：`systemctl show -p WorkingDirectory m20-ai-detect`；换路径要同步改 unit 4 处（§1.3） |

**结论（回答"空目录 or 复制后自身"）**：
- 两者都可以，**本质是同一个要求——BASE 必须是项目根那一层**；
- **推荐"空目录 + 项目自己当根"**（情形 ①/② 都是这个形态）：数据目录（`raw/ results/ saved/`）
  直接长在项目根下，备份/迁移/清理都是"一个目录"的事；
- **不要**把 BASE 设成"上级目录"（如 `/home/user` 或 `辅助工具/`），否则数据会散落在上级目录里，
  而且 `install.sh` 的同步会把整层目录都算进去。

选好后用预检查确认：`bash deploy/preflight.sh --base <BASE>`（第 4 组会直接判"空目录/已是本工程/不可写"）。

### 1.1 只传一个子目录，不是整个「辅助工具」

`辅助工具/` 里只有一份东西是**要上机**的：

| 路径 | 上机？ | 说明 |
|---|---|---|
| `m20-ai-detect/` | ✅ **只传它** | 采样器 + Web 控制台 + 部署脚本（约 1.5 MB 代码，不含本地缓存） |
| `M20视频流AI检测-接入测试与实施方案.md` | ❌ | 方案资料，留在本地 |
| `视频检测接口.md` | ❌ | AI 接口文档，留在本地 |
| `add-m20-route.bat` | ❌ | **Windows 专用**（在 PC 上加静态路由），Linux 上没用 |

而且**不要手动复制，用 `install.sh`**：它会先备份、再同步、再远端 `import` 自检，并自动排除
运行数据（`spool/ raw/ results/ alerts/ saved/ log/ tmp/`）和本地产物（`.playwright-cli/`
约 5 MB 的截图、`.pytest_cache/`、`__pycache__/`、虚拟环境）。

### 1.2 路径的四条硬要求

> ⚠️ 本工程里 **代码目录 = 数据目录**：`store.py` 在 `M20AI_BASE_DIR`（默认就是项目根）
> 下建 `spool/ raw/ results/ alerts/ log/ tmp/`。所以"代码放哪"直接决定"数据写哪"。

1. **必须与 systemd unit 里写死的 4 处一致**（否则服务起不来）：
   `WorkingDirectory`、`EnvironmentFile`、`Environment=PYTHONPATH`、`ReadWritePaths`。
2. **必须 `user` 用户可写**：`install.sh` 以 `user` 同步、服务也以 `User=user` 运行。
3. **必须是本地 POSIX 文件系统**：不要放 `/tmp`（重启即丢）、不要放 `/opt/robot/`（厂商目录，
   升级会被覆盖）、不要放 `/root`（权限）、不要放 U 盘/NTFS/网络盘（丢权限位、可能带 CRLF）。
4. **纯 ASCII 路径、无空格**：避免 unit 与 shell 里的转义问题。

**推荐路径**：

| 场景 | 路径 |
|---|---|
| 104（现状，沿用不要动） | `/home/djw/m20-ai-detect` |
| 新机器（无 `/home/djw` 约定） | `/home/user/m20-ai-detect`（更自然，但**必须改 unit 4 处**） |

### 1.3 换路径要改哪些地方（照抄即可）

以新路径 `/home/user/m20-ai-detect` 为例：

```bash
# ① 两个 unit 各 4 处（detect 与 console 都要改）
sudo sed -i 's#/home/djw/m20-ai-detect#/home/user/m20-ai-detect#g' \
  /etc/systemd/system/m20-ai-detect.service \
  /etc/systemd/system/m20-ai-console.service
sudo systemctl daemon-reload

# ② env 里的数据目录（必须与 unit 一致）
sed -i 's#^M20AI_BASE_DIR=.*#M20AI_BASE_DIR=/home/user/m20-ai-detect#' \
  /home/user/m20-ai-detect/m20-ai-detect.env

# ③ 目录权限（bootstrap.sh 里是 750）
chmod 750 /home/user/m20-ai-detect
```

不改 unit 只改 env 是最常见的翻车方式：服务能起，但 `ReadWritePaths` 指向旧路径，
写 `raw/` 时被 systemd 的沙箱拦下（表现为"采集没数据、日志里 permission denied"）。

### 1.4 三种传输方式对比

| 方式 | 评价 |
|---|---|
| `./deploy/install.sh`（rsync / tar over ssh） | ✅ **推荐**。自动备份 + 排除数据目录 + 远端自检；可重复执行 |
| 手动 `scp -r` / `tar czf - \| ssh` | ⚠️ 可行，但**必须自己排除** `spool/raw/results/saved/`，否则会把几十 MB 旧数据糊上去；还要保留执行位（`chmod +x deploy/*.sh deploy/aiDetect`） |
| U 盘 / Windows 直接拷 | ❌ 会带 **CRLF 行尾**（`bad interpreter ^M`）并**丢失可执行位**；非要这么做，落地后先 `dos2unix` + `chmod +x`，再跑 `install.sh` 自检 |

### 1.5 两种部署入口怎么选

| | **入口 A：从外部主机推** | **入口 B：先拷到 M20 再就地部署** |
|---|---|---|
| 前置 | 开发机能 SSH 到目标机（配好别名/免密） | 代码已拷到目标机的旁路目录 |
| 第一条命令 | `./deploy/install.sh user@<IP> --no-restart` | `bash deploy/install-local.sh --from <dir\|tar.gz>` |
| 适合 | 日常迭代、能联网、改一行就推 | 首次装机、现场离线、只有一份文件夹 |
| 详细步骤 | 第 4 节 | 第 10 节 |

**决策规则**：
- 如果你**已经能 `ssh <别名> echo ok`** → 走 A（自动跑测试、镜像同步、远端自检，最省事）；
- 如果**手上只有文件夹/U 盘/压缩包**，或现场没网 → 走 B；
- 两者可混用：首次用 B 装机，之后用 A 迭代。

## 2. 准备 SSH 访问（别名可选）

**推荐直接用 `user@IP`，不需要配任何别名**（部署命令里现写现用，最不容易搞混）：

```bash
./deploy/install.sh user@192.168.0.196 --check     # 先测通不通
./deploy/install.sh user@192.168.0.196 --no-restart
```

如果你更喜欢别名，再在开发机的 `~/.ssh/config` 里加（名字自定，本文用 `m20pro2-GOS`）：

```
Host m20pro2-GOS
    HostName <新GOS的IP>
    User user
```

验证：`ssh -o BatchMode=yes m20pro2-GOS 'echo ok'`
（免密没配就先投公钥：`ssh-copy-id user@<IP>`）

## 3. 改配置（**新机器必须改的 6 项**）

部署前把仓库里的 `deploy/m20-ai-detect.env.example` 按新机器改一遍，
或部署完直接改远端 `~/m20-ai-detect/m20-ai-detect.env`（**推荐后者**，见步骤 4.4）。

| 变量 | 现值（104） | 新机器怎么填 |
|---|---|---|
| `M20AI_SRC_F` / `M20AI_SRC_B` | `rtsp://10.21.31.103:8554/video1/2` | 换成**新机 AOS 的内网 IP**（若同网段仍是 103 则不变） |
| `M20AI_AI_BASE` | `http://jsxy.aihyzh.com:30881` | AI 服务地址；**多机共用一套服务时，确认配额/并发够用** |
| `M20AI_BASE_DIR` | `/home/djw/m20-ai-detect` | 保持默认最省事（见下方"路径"警告） |
| `M20AI_ENABLE_F/B` | `1 / 0`（按当前实际填） | 新机实际接了哪些相机就开哪些 |
| `M20AI_CAP_ID` / `PARAMS_JSON` | `ai-04-yolov8-object-detection` | 若 AI 服务换了模型，改能力 ID |
| `M20AI_SPOOL_MAX_FILES` | `600` | 保持默认；相机多/帧率高高时按 `路数×600s` 调 |

**路径警告**：两个 systemd unit 里 `/home/djw/m20-ai-detect` 是**写死的 4 处**
（`WorkingDirectory`、`EnvironmentFile`、`Environment=PYTHONPATH`、`ReadWritePaths`），
`.env` 里的 `M20AI_BASE_DIR` 必须与之一致。**新机器想换路径（如 `/home/user/m20-ai-detect`）时，
要同时改 unit，否则服务起不来**。
`/home/djw` 是 104 上的历史约定（root 所有 + ACL 授权 `user`）；新机器若无此目录，
`bootstrap.sh` 以 `PROJ_ROOT` 为基准仍可工作，但 unit 必须跟着改。

## 4. 模式 A：三步部署（从开发机推送）

> 如果你**不想从开发机推代码**，而是先把文件夹拷到机器上再就地覆盖 —— 直接看 **第 10 节「模式 B」**。
> 两种模式产出的结果一样，选顺手的即可。

### 4.1 同步代码（不重启）

```bash
cd 辅助工具/m20-ai-detect
./deploy/install.sh user@<新GOS-IP> --no-restart
```

脚本会做 6 件事：本地跑测试（262 项）→ 检查禁用关键词（`push_video`/`v4l2`/`gst-launch`，
会被机器人侧 `restart.sh` 的 pkill 误杀）→ 检查 CRLF → 远端备份 → 同步 →
远端 `import` 自检。**首次部署一定要加 `--no-restart`**（服务还没装 unit，重启会失败）。
（等价的旧写法 `NO_RESTART=1 ./deploy/install.sh ...` 仍然可用，推荐用新写法。）

### 4.2 首次引导（在目标机上跑）

```bash
ssh user@<新GOS-IP>
cd ~/m20-ai-detect && bash deploy/bootstrap.sh
```

它会：检查/安装 `ffmpeg`、`python3` → 建 `spool/ raw/ results/ alerts/ log/ tmp/` →
生成 `m20-ai-detect.env`（已存在则跳过）→ 装 unit + `daemon-reload` → 装 logrotate →
**跑 `doctor` 门禁**（AI 服务/相机源/时钟/磁盘）。doctor 不全绿就停下按提示排查，
不会盲目启动服务。

> GOS 的 sudo 口令是**半角单引号 `'`**（`printf "'\n" | sudo -S ...`），脚本已内置。

### 4.3 装控制台（可选，但通常要）

```bash
ssh user@<新GOS-IP> 'cd ~/m20-ai-detect && bash deploy/console-bootstrap.sh'
```

它会：生成 `m20-ai-console.env`（默认监听 `5050`）→ 装 root helper
`/usr/local/sbin/m20-ai-console-helper` + sudoers 白名单（`visudo -c` 校验）→
装 `aiDetect` 命令 → 装控制台 unit → **前台冒烟 5 秒**（验 `/api/status` 与首页都 200）→
启动常驻。

### 4.4 按新机器改 env 并重启

```bash
ssh user@<新GOS-IP>
vi ~/m20-ai-detect/m20-ai-detect.env     # 改第 3 节里那几项
sudo systemctl restart m20-ai-detect     # 改 env 必须重启（systemd 不热读）
```

改了控制台的 env 则重启 `m20-ai-console`。

## 5. 验收清单（逐条打勾）

> 建议先复跑一次体检确认没有 FAIL：`bash deploy/preflight.sh`

```bash
# ① 门禁
ssh user@<新GOS-IP> 'cd /home/djw/m20-ai-detect && set -a && . ./m20-ai-detect.env && set +a && PYTHONPATH=src python3 -m m20_ai_detect doctor'

# ② 服务状态
ssh user@<新GOS-IP> 'systemctl is-active m20-ai-detect m20-ai-console'

# ③ 取帧（两种来源都要能出图）
ssh user@<新GOS-IP> 'curl -s "http://127.0.0.1:5050/api/snapshot?cam=front" | head -c 120'

# ④ 开采集 30 秒，看有没有真的落盘
ssh user@<新GOS-IP> 'curl -s -X POST http://127.0.0.1:5050/api/service -H "Content-Type: application/json" -d "{\"action\":\"start\"}"'
#   等 20s 后：
ssh user@<新GOS-IP> 'ls -lt /home/djw/m20-ai-detect/raw/front | head -3; ls /home/djw/m20-ai-detect/spool/front | wc -l'
```

浏览器打开 `http://<新GOS>:5050/`，确认：指标卡有数、相机画面能出图、日志有内容、
「检测数据」与留存卡对得上。

**关键观察点**：`/api/snapshot` 返回的 `source` 应该是 `ring`（采集运行时读本地帧，~60ms）；
若一直是 `live`，说明采集没在正常落盘（先看 `journalctl -u m20-ai-detect -n 30`）。

## 6. 主机侧优化（建议一起做，104 上已验证）

| 项 | 作用 | 做法 |
|---|---|---|
| rsdriver 日志限流 | 雷达驱动刷屏占整机 journal 94.7%（295 MB/天） | 见 README §6.1 的 drop-in（`LogRateLimitBurst=30`） |
| journal 上限 | 防止 journal 无限涨 | 控制台留存卡设 `SystemMaxUse=200M`，或 `journalctl --vacuum-size=200M` |
| 文件日志轮转 | log/ 保留 7 天 | `bootstrap.sh` 已装 `/etc/logrotate.d/m20-ai-detect` |
| 开机自启 | 按需 | **默认不 enable**（ADR-008：重启后手动起）；要自启：`sudo systemctl enable m20-ai-detect m20-ai-console` |

## 8. 已知坑（都在 104 上踩过）

| 坑 | 症状 | 处理 |
|---|---|---|
| **CRLF 行尾** | `bad interpreter: /usr/bin/env bash^M` | `install.sh` 会拦；`dos2unix` 转换 |
| **禁用关键词** | 机器人侧 `restart.sh` 的 pkill 把你的进程一起杀了 | 源码/命令行不得出现 `push_video`、`v4l2`、`gst-launch`（install.sh 会拦） |
| **sudo 口令** | `sudo` 一直要密码 | 口令是半角单引号 `'`；脚本内置 `printf "'\n" \| sudo -S` |
| **heredoc 覆盖管道** | sudo 报 "Sorry, try again" ×3 | 同一命令里既有 `\| sudo -S` 又有 heredoc 时，**heredoc 会顶掉管道**；改成"先写文件再 sudo cp" |
| **helper/sudoers 没装** | 控制台启停服务失败（`sudo -n` 不通） | 必须跑 `console-bootstrap.sh`；`install.sh` **不装** helper |
| **GOS 无公网** | AI 服务 curl 超时/`Errno -3 name resolution` | 走 AOS 转发（ADR-003）；先测 `ping <AOS内网IP>` 与 `curl <AI_BASE>` |
| **PTP 拖时钟** | 日志时间跳回 2024 | `M20AI_TS_OFFSET_SEC=0` 自动测量（ADR-004），别硬改系统时间 |
| **相机"掉线"其实是供电被关** | `/dev/video*` 消失、HLS 404 | 查 AOS 控制台「相机供电」开关，别先怀疑 USB/线缆 |
| **raw 文件 mtime 是原始帧时间** | 用 `ls -lt` 看似"很久没更新" | 用 `stat -c %z`（ctime）看真正落盘时刻 |
| **spool 无上限（已修）** | AI 挂一夜写十几 GB | v0.8.12 起有 `M20AI_SPOOL_MAX_FILES=600` |
| **两套机器共用 AI 服务** | 配额/并发打满，两边都超时 | 确认服务端并发；必要时错峰或分能力 ID |

## 9. 两套 M20 同时运行的注意点

1. **端口不冲突**：都在各自 GOS 上监听 5050，互不影响。
2. **目标要分清**：直接在命令里写 `user@<IP>`（不依赖 ssh 别名），两台机器就不会串；若用别名，`HOST=` 切换前先 `ssh <别名> hostname` 确认。
3. **AI 服务并发**：两边各 2 路 1fps，合计 4 req/s 量级；先确认服务端撑得住。
4. **数据各自独立**：`/home/djw/m20-ai-detect/{raw,results,saved}` 是本地目录，天然隔离。
5. **对比验证**：两套用同一 `CAP_ID` + `PARAMS_JSON`，否则检出结果不可比。

## 10. 模式 B：先复制到机器，再就地覆盖（离线部署）

适用：手上只有一份 `m20-ai-detect` 文件夹/压缩包，想直接放到目标机上更新，不经过开发机的 rsync。

### 10.1 一句话回答"复制到哪"

**复制到项目最终要待的位置**（即 `M20AI_BASE_DIR`，默认 `/home/djw/m20-ai-detect`）。
建议**不要直接覆盖**，而是先放到**旁路目录**，交给脚本做白名单覆盖——这样有备份、有自检、不碰数据：

```bash
# 1) 把新代码放旁路（任选其一）
scp -r m20-ai-detect user@<GOS>:/home/user/m20-ai-detect-new      # 目录
scp m20-ai-detect-v0.8.12.tar.gz user@<GOS>:/home/user/           # 或压缩包

# 2) 在目标机上就地覆盖（自动备份 + 白名单覆盖 + 自检 + 重启）
ssh user@<GOS>
cd /home/djw/m20-ai-detect
bash deploy/install-local.sh --from /home/user/m20-ai-detect-new        # 目录
bash deploy/install-local.sh --from /home/user/m20-ai-detect-v0.8.12.tar.gz
```

如果你**已经直接把文件夹拖/拷覆盖到了目标目录**，那就不需要 `--from`，
跑一遍下面这条即可（它做备份 → 清垃圾 → 修行尾/权限 → 自检 → 重启）：

```bash
cd /home/djw/m20-ai-detect && bash deploy/install-local.sh
```

### 10.2 它到底做了什么（安全边界）

| 行为 | 说明 |
|---|---|
| **只覆盖代码白名单** | `src deploy tests docs webconsole Makefile pyproject.toml README.md USAGE.md`；`spool/ raw/ results/ alerts/ saved/ log/ tmp/`、`.env`、`.backup/`、`.runtime/` **一律不碰** |
| **覆盖前先备份** | `.backup/code-<TS>.tar.gz` + `.backup/env-<TS>`，回滚只需一条命令 |
| **路径一致性硬检查** | 比对 `BASE` 与 unit 的 `WorkingDirectory`，不一致**直接拒绝**并打印修复命令（`--force` 可跳过）——这条防的是"服务能起但写 `raw/` 被 systemd 沙箱拦" |
| **清理 Windows 垃圾** | `.playwright-cli/`（本地截图 5 MB）、`.pytest_cache/`、`__pycache__/`、`*.pyc` |
| **修行尾与执行位** | CRLF→LF（Windows 拷贝必需）、`chmod +x deploy/*.sh deploy/aiDetect` |
| **自检不过不重启** | 先 `compileall` 再 `import` 打印版本；失败就停，**旧代码继续跑**，不会让服务躺在坏代码上 |
| **幂等** | 可反复执行；`--dry-run` 只打印计划不落盘 |

其他参数：`--base <dir>` 指定项目根、`--no-restart` 只更新不重启、`--dry-run` 预演、`--force` 跳过路径检查。

### 10.3 与模式 A 的区别

| | 模式 A（`install.sh`，开发机上跑） | 模式 B（`install-local.sh`，机器上跑） |
|---|---|---|
| 前提 | 开发机能 SSH 到目标机 | 代码已拷到目标机 |
| 同步方式 | rsync/tar over ssh，**镜像**（多余旧文件会被删） | tar 覆盖白名单，**不删**多余旧文件 |
| 本地跑测试 | ✅ 部署前跑 262 项 | ❌ 机器上不跑（只做 compileall+import） |
| 备份/自检 | ✅ | ✅ |
| 适合 | 日常迭代（改一行就推） | 首次装机、无开发机、离线现场 |

> 差异提醒：模式 B **不删除**源里已不存在的旧文件（例如某次重构删掉的模块）。如果担心残留，
> 覆盖后手动 `git status`（若有仓库）或对比 `src/` 文件清单；日常迭代仍建议用模式 A。

### 10.4 已验证

在 104 上实测：`--dry-run` 两种场景（无参数 / `--from`）计划输出正确；
真实执行一遍：备份 → 清理 → 修行尾/权限 → `import ok, sampler v0.8.12, console v0.8.12` →
两个服务 `active`，回滚包落在 `.backup/code-<TS>.tar.gz`。
