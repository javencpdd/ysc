# ADR-009: 受限只读文件浏览（`/api/files` + `/api/file`）

- 日期：2026-10-16
- 状态：已实施
- 关联：ADR-005（控制台与提权）、ADR-006（响应留存）、ADR-008（时间轴与留存清理）

## 背景

用户问"这些保存的图片还有日志都是在哪地址，我能不能通过 web 来查看这些文件"。

排查后的事实：

- 数据全在 GOS（10.21.31.104）`/home/djw/m20-ai-detect/` 下五个目录 ——
  `saved/`（标注结果图 + 响应 JSON 成对）、`raw/`（原始帧环形缓冲）、
  `results/`（JSONL 权威记录）、`spool/`（待推理帧）、`log/`（采样器日志）。
- 控制台**已经能 Web 查看**的部分：`/api/saved/img`（图片）、`/api/response`（单帧响应 JSON）、
  `/api/recent`（今日 JSONL 尾部）、`/api/logs`（journal）。
- **看不了**的部分：`raw/` 原始帧、`results/` 完整 JSONL 文件下载、`saved/*.json` 原文件本体、
  `log/sampler.log`。这些只能 SSH 上去 `ls`/`cat`。

需要一个"文件浏览器"式的入口，但绝不能变成任意文件读取（工程代码、env、系统文件都在这台机器上）。

## 决策

### 1. 白名单根 + 两级校验，而不是黑名单过滤

只允许进入五个**一级目录**：

```python
FILE_ROOTS = ("saved", "raw", "results", "spool", "log")
```

路径校验 `_safe_rel_path()` 逐段检查：

- 拒绝空、以 `/` 开头、含 `\`、含 `..`；
- 按 `/` 切段，段数 ≤ 8，每段必须匹配 `[A-Za-z0-9._-]+`；
- **首段必须落在 `FILE_ROOTS`** —— 这一条是核心，`src/`、`m20-ai-detect.env`、`/etc/passwd` 全部在此被拒。

`_resolve_under()` 在此之上再补一次 `realpath` 前缀比对，堵住符号链接指向工程外的可能。

> 为什么不用黑名单：黑名单要靠枚举所有"不该被读"的路径，漏一条就是事故。
> 白名单的默认值是"拒绝"，新增目录必须显式加进 `FILE_ROOTS`。

### 2. 两个只读接口

| 接口 | 参数 | 说明 |
|---|---|---|
| `GET /api/files` | `dir=`（相对路径，空=根）、`n=`（1–2000，默认 300）、`match=`（名称子串过滤） | 列目录。根层只列出白名单根；子目录内**目录在前、文件按 mtime 倒序**；返回 `entries[{name,path,type,size,ts}]` + `parent` + `truncated` |
| `GET /api/file` | `path=`（相对路径）、`tail=N`（读文本末尾 N 行，≤5000）、`dl=1`（附 `Content-Disposition: attachment`） | 读单文件。Content-Type 按扩展名映射（jpg/png/json/jsonl/log/txt/md/yml） |

### 3. 大文件必须走 `tail`，不允许整读

- 整读上限 `FILE_MAX_BYTES = 32 MB`，超过返回 **413** 并提示改用 `tail=N`；
- `_tail_bytes()` 从文件尾回读 64KB 块直到凑够 N+1 个换行，**不整读**（`results/20261016.jsonl` 单日可到数 MB，`raw/` 单图 ~85KB 但目录 209MB）。

### 4. 前端"数据文件（只读浏览）"卡片

面包屑（上一级按钮 + 当前路径）、名称过滤框、文件列表（目录可点击下钻、文件点击预览）、
每张图/文本文件提供"下载"直链；文本预览默认读末尾 200 行（可调 1–5000），图片直接 `<img>` 显示。

写入 `refreshAll()`，随页面其他卡片一起刷新。

### 5. 仍然只读

两个接口全部走 `do_GET`，没有任何写/删/改分支；`/api/file` 的 `dl=1` 只是加响应头，不落盘。

## 依据

- 实测（104）：`raw/` 209MB、`results/` 8.6MB 共 3 个文件、`saved/front/` 224 对。
  完整 JSONL 单文件已达 3.4MB 且持续增长 —— 这是必须支持 `tail` 的直接原因。
- 安全断言由单测固化：`/api/files?dir=` 传入 `../..`、`/etc`、`src`、`saved/../../src`、`saved/..`
  全部 400；`/api/file?path=` 传入 `src/secret.py`、`../m20-ai-detect.env`、`/etc/passwd`、
  `results/../../etc/passwd` 全部 400。测试里真的造了一个 `src/secret.py` 诱饵文件。
- 单测 **160 项全绿**（新增 `TestReadOnlyFiles` 11 项）。

## 后果

### 正面

- 五类数据文件全部可在浏览器里浏览/预览/下载，不必再 SSH；
- 图片与 JSON 直出、大文本 `tail`，磁盘与内存压力可控；
- 白名单 + 两级校验 + 单测诱饵，把"任意文件读取"这条路堵死在接口层。

### 负面 / 代价

- 只覆盖五个数据目录；将来若要把 `bad/`（隔离帧）等新目录纳入，必须改 `FILE_ROOTS` 并补单测；
- 文件名必须是 ASCII 且匹配 `[A-Za-z0-9._-]+`（当前所有落盘文件均满足，无影响）；
- 目录列表不做递归，深层目录需逐级点开（`results/` 本就只有一层）。

### 触发复审的条件

- 出现需要在线编辑/删除文件的诉求（当前严格只读，届时需另立 ADR 设计提权边界）；
- 需要浏览白名单之外的新目录；
- 单文件体量增长到 `tail` 也不够用（需引入分页/范围请求 `Range` 头支持）。
