# ADR-013: 控制台界面中英适配（可切换语言）

- 日期：2026-10-17
- 状态：已实施
- 关联：ADR-005（控制台）、ADR-011（留存与清空）、ADR-012（相机画面）

## 背景

用户要求："整体界面做一个中英的适配？可以切换语言"。

约束与现状：
- 控制台是**零依赖单页**（`webconsole/static/index.html`，原生 JS，无构建、无 npm），
  不可能引 i18next/vue-i18n 等框架；
- 用户可见文案分两类：**前端静态/JS 拼装**（约 200 条）+ **后端接口返回的
  detail/notes/error**（约 60 条，含带计数的参数化文案，如清空统计）；
- 使用场景偏演示/协作，**中文仍是默认**，英文是打开给非中文协作者看的。

## 决策

### 1. 语言不落库、不进 URL：请求头 `X-Lang` + 前端 localStorage

- 前端 `m20ai-lang`（localStorage）记住选择，默认 `zh`；每次 `fetch` 由 `api()`
  统一带 `X-Lang: zh|en` 头；`setLang()` 切换后重新 `refreshAll()`。
- 后端 `i18n.pick_lang(headers)`：缺省或非 `en` 开头一律 `zh`——**存量测试与 CLI
  调用零影响**（不传头就是中文，与原行为逐字节一致）。
- 不用 URL query 参数：切换语言不该污染/破坏可分享的 URL 语义（本控制台本来也没有
  深链接需求）。

### 2. 后端文案目录（`webconsole/i18n.py`）——单一事实来源

- `MSG: {键: (中文, English)}`，`fmt(key, lang, **params)` 用 `{name}` 占位替换；
- 只覆盖 **server.py 自身拼装**的文案（detail/notes/error），约 60 条；
- 缺键回退为键名（单测可发现漏译）。

**有意的覆盖边界**：核心模块（config/envfile/sysactions/store/capture）抛出的校验
异常原文仍是中文——它们是"用户输错了"时的边缘提示（<10 条），逐个本地化性价比低；
快照模块的失败返回带 `code`，由 server 映射成目录文案（`snap.*`）。
将来若要把核心校验错误也英文化，触发复审条件见下。

### 3. 前端内嵌 JSON 词典 + `data-i18n` 标记

- `<script type="application/json" id="i18n-data">` 内嵌 `{zh:{...}, en:{...}}`
  （205 键）：JSON.parse 加载，**不新增静态文件路由**（服务本来只发 `/`，避免
  为新文件引入新的攻击面）；
- 静态文案用 `data-i18n`（textContent）/ `-ph`（placeholder）/ `-title`（title）/
  `-html`（含 `<b>`/`<code>` 的富文本，值来自自家常量，无 XSS 面）；
- JS 拼装文案统一走 `t(key, vars)`；序列分隔符等语言相关差异收进
  `listSep()` 与 `notes.join` 键。

### 4. 质量门禁：词典一致性单测

`tests/test_webconsole.py::TestI18nDict` 解析 index.html：
双语键集合必须一致、无空值、**data-i18n/JS `t()` 引用的键必须都存在、字典里不许有死键**。
（JS 三元动态引用的 `alert.chip_on/off` 在测试里显式声明。）
另加 3 个 HTTP 测试：`X-Lang: en` 下 retention note / config detail / 快照错误均为英文，
不带头仍是中文。

## 实施

- `webconsole/i18n.py`（新）：`MSG` 目录 + `pick_lang()` + `fmt()`。
- `webconsole/server.py`：`Handler._lang()/_t()`，所有自拼文案切到目录；
  `_purge_with_restart(..., lang=)` 透传；`snapshot.py` 失败返回带 `code`
  （no_cameras/unknown_cam/grab_failed）+ 参数，server 映射为 `snap.*`。
- `webconsole/static/index.html`：i18n JSON（234 键）+ 顶栏 中文/EN 切换 +
  全量 `data-i18n*` 标记 + JS `t()` 化；`api()`/`fbText()`/单帧检测 fetch 带 `X-Lang`。
- 测试：223 → **228 项**（+5：词典 2 + X-Lang HTTP 3）。
- 版本：0.7.1 → **0.8.0**。

## 验证（GOS 104 真机）

`NO_RESTART=1` 同步 + 只重启控制台后：
- `GET /api/status` → `version=0.8.0`；
- `GET /` 含语言切换按钮与 i18n JSON；
- `curl -H "X-Lang: en" /api/retention` → note 为 "env-level changes apply after restarting
  the sampler；..."；不带头中文不变（回归）。

## 触发复审的条件

- 要把 config/envfile/sysactions 的**校验错误**也英文化 → 给核心模块加 lang 透传或错误码；
- 语言需求超过两种 → 词典改按语言文件拆分（届时先加静态文件路由与相应安全约束）；
- CLI（aiDetect）也要求多语言 → 属另一个交付面（终端工具），单独 ADR。

## 修订记录 2026-10-17（v0.8.2）：界面不再裸露系统英文原文

**问题**：「journal 占用」指标卡直接显示 `journalctl --disk-usage` 的原句
"Archived and active journals take up 200.0M in the file system."——系统命令
的英文输出不属于本工程的用户可见文案，违反 ADR-013 初衷（切到中文仍有一块
英文）。

**决策：解析在服务端，渲染在前端。**
- `sysactions.journal_disk_usage()` **保留**（排障可能要整句原文，且 CLI 可能复用）；
- 新增 `journal_disk_bytes()`：正则解析原文里的"数值 + 单位"（注意原文单位
  **不带 B**——是 `200.0M` 而非 `200.0MB`；同时兼容 `K/KB`、`M/MB`、
  `G/GB`、`T/TB`、纯 `B`），失败返回 `None`（前端显示 –）。
- `/api/status` 与 `/api/retention` 的字段由 `journal_usage`（英文整句）改为
  **`journal_bytes`（数字）**，语言无关；前端 `fmtMB()` 格式化成
  "200.0 MB"，中文/英文下都自然。
- 指标卡数值下方新增一行说明（`metric.journal_full`，双语）：点明这是
  "归档 + 活跃日志"的合计、且属系统日志而非本工程数据（顺带回答用户此前
  问过的"这 200M 是什么、怎么一直在"）。

**验证**：真机 `/api/status` → `journal_bytes=209715200`（200 MB），响应体
不含英文原句；前端中文渲染为「200.0 MB」+ 中文说明行。单测 +9（解析器
7 + HTTP 契约 2），229 → **238 项**。版本 0.8.1 → **0.8.2**。

## 修订记录 2026-10-17（v0.8.6）：指标口径统一——「检测数据」上位，journal 归位

**问题（用户连续两次问"这个和下面的数据对不上"）**：顶栏「journal 占用
208.0 MB」与下方卡片里的 KB 级数字（saved 717 KB / results 307 KB / raw 20.3 MB）
并列展示，两个数字来自**完全不同的存储池**却挨在一起，极易被理解为"同一本账
对不上"。实测构成：整机 journal 208 MB 中——

| 单元 | 行数 | 占比 |
|---|---|---|
| `rsdriver.service`（厂商驱动） | 197,298 | **94.7%** |
| `ptp_manage.service` | 9,998 | 4.8% |
| **`m20-ai-detect.service`（本工程）** | **349** | **0.2%** |

本工程在 journal 里几乎可以忽略；大头是厂商服务刷屏。而 `journalctl --disk-usage`
**会忽略 `-u` 过滤器**（systemd 明确行为），所以"本服务占多少"没有官方命令——
只能按文本量估算。

**决策：把两个口径拆到各自该在的位置。**
1. 顶栏第五项改为「**检测数据**」= `raw+results+saved+spool` 合计（副行列四项
   明细），与留存卡「清理数据」逐项一致——**用户能直接对上**；
2. 整机 journal 的占用与构成挪到「日志与数据留存策略」卡 journal 区首行
   （`ret.journal_now`），形如：`当前整机 journal ≈ 200.0 MB（含所有 systemd
   单元；本服务 m20-ai-detect 仅 385 行 ≈ 26 KB，大头是厂商 rsdriver 等系统服务）`；
3. 新增 `sysactions.journal_service_usage(unit)`（`journalctl -u X -o cat` 统计
   行数/文本字节，失败返回 `None`），`/api/retention` 返回 `journal_service` 字段；
   `journal_disk_usage()` / `journal_disk_bytes()` 保留（原文 + 整机字节数）。

**验证（浏览器实拍，v0.8.6）**：中文渲染 `检测数据 22.9 MB`、
`raw 20.3 MB · results 307 KB · saved 717 KB · spool 1.6 MB`（与用户截图里
「清理数据」的四项**完全一致**）；EN 同构。单测 246 → **249 项**。
词典 216 → **217 键**（删 `metric.journal`/`metric.journal_full`，增
`metric.data`/`metric.data_note`/`ret.journal_now`）。
