# ADR-014：留存策略卡「两个保存按钮」语义澄清

- 状态：已采纳并部署（v0.8.1，2026-10-17）
- 相关：ADR-006（响应留存条件）、ADR-008（`saved/` 留存清理）、ADR-010（单位语义）、ADR-011（关注目标与数据清空）、ADR-013（中英适配）

## 背景

「日志与数据留存策略」卡同时承担三类开关：**留存条件**（`M20AI_SAVE_MODE`，决
定一帧够不够格进 `saved/`）、**容量与时长**（`M20AI_RING_MAX_MB` /
`M20AI_RESULTS_KEEP_DAYS` / `M20AI_SAVED_MAX_MB` / `M20AI_SAVED_KEEP_DAYS`，
决定每个目录最多留多少、留多久）、**日志侧**（journal 清理 / journald 上限 /
logrotate）与**数据清空**（ADR-011）。

原 UI 把前两类的输入框混排在同一个 `<div>` 里，末尾并排两个按钮：

```
[ 保存存储留存（重启后生效） ]  [ 保存留存条件（重启后生效） ]
```

问题（2026-10-17 用户实测反馈）：

1. **两个按钮名字太像**——只差两个字，肉眼扫过分不清哪个管"存哪些帧"、哪个管
   "留多少"；
2. **按钮与参数不挨着**——左按钮管上面 4 个数值框，右按钮管中间那个下拉框，
   但两个按钮都在最底部并列，点错的代价是"以为改过了、其实没改"（或反之，
   误改了另一类配置）；
3. 唯一的说明 note（`ret.env_note`）把单位说明、`saved/` 清理节奏、
   `alert` 语义、磁盘参考四件事揉在一段里，找不到"这两个按钮到底差在哪"。

## 决策

**最小侵入改造，不动后端、不动接口契约**（`POST /api/retention` 的字段与语义
完全不变，仅前端呈现方式变更）：

1. **拆成两节，按钮各自贴着参数**（顺序由"闸门"到"配额"，符合认知顺序）：
   - ① **留存条件** —— `SAVE_MODE` 下拉 + 「保存留存条件」按钮
   - ② **容量与时长** —— 4 个数值框 + 「保存容量与时长」按钮
2. **按钮文案点明维度**，不再用含糊的"存储留存"：
   - 「保存**容量与时长**（重启后生效）」← 管 `raw/`/`results/`/`saved/` 的上限与天数
   - 「保存**留存条件**（重启后生效）」← 管 `SAVE_MODE` 准入（只管 `saved/`）
3. **每节配一段"只管什么、与什么无关"的 note**：
   - ① note 明确 `raw/`、`results/` **与此无关**（关键是破除"改 SAVE_MODE 能
     省 raw 盘"的误解）；
   - ② note 明确四个框是**四个互不相干的维度**，改一个不影响其它三个，并写出
     三种清理节奏（`raw/` 每轮、`saved/` 每 10 分钟、`results/` 每小时）。
4. `ret.env_note` 瘦身：只留单位说明 + 清理节奏 + 磁盘参考，删掉与 ① note
   重复的 `alert` 语义描述。

## 验证

- 单测：`python3 -m unittest discover -s tests` → **229 项全绿**（+1）。
- 部署：`NO_RESTART=1 ./deploy/install.sh` + `console-restart`（采集器未被
  重启，与部署约束一致）。
- 真机（104，v0.8.1）：
  - `console 0.8.1`；
  - zh/en 下两节标题、两按钮、两 note 均正确渲染，双语一致；
  - 点「保存容量与时长」（不改动）→ 返回 note「env 级已写入（重启采集后生
    效）」，env 文件内容不变（幂等）；
  - 点「保存留存条件」→ 同样只写 `M20AI_SAVE_MODE` 一个键，`grep env` 验证
    未误写其它 4 个键。

## 复审触发条件

- 留存卡再新增第三类开关（如 `spool/` 上限、`alerts/` 策略）时，应重新评估
  是否升级为"分 tab / 分组表单"而非继续堆小节。
- 若 `saveEnvRetention()` 与 `saveSaveMode()` 的后端字段发生合并或拆分
  （例如让 SAVE_MODE 也走 `/api/config`），需同步本 ADR 与单测。
