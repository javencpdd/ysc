# ADR-008: 目标图片时间轴与 saved/ 留存清理（含开机自启默认关闭）

- 日期：2026-10-15
- 状态：已接受
- 影响面：`src/m20_ai_detect/{config,store,sampler}.py`、`webconsole/{server.py,static/index.html}`、`deploy/{m20-ai-console-helper,m20-ai-console.sudoers,aiDetect,bootstrap.sh,console-bootstrap.sh,m20-ai-detect.env.example}`、README/USAGE、版本 0.5.0

## 背景

用户两条新需求（原话）：

1. **"能不能直接将 ai 检测目标的图片带上时间戳保存，然后可以在左边卡片窗口中滑动时间条来查看"**——ADR-006 解决了"条件留存"，但没有"按时间浏览"的界面；而且留存文件用的是**帧名**（相机时钟域，2024 年），不能直接当"时间戳"用。
2. **"关闭开机自动启动服务，我自己会启动"**——两个部署脚本（bootstrap.sh / console-bootstrap.sh）此前一直强制 `systemctl enable`。

三个数据事实决定了设计（都有实测/文档依据）：

- `raw/` 环形缓冲仅 200 MB（1 fps ≈ 3 分钟窗口）→ 时间轴**不能**建立在 raw/ 上，必须以 `saved/` 为数据源；
- 真实时间只存在于 JSONL 的 `ts`（ADR-004 时钟修正后）；帧名里的 2024 时间是相机时钟，不可作准；
- ADR-006 复审条件①早已预告：`any` 模式 ≈ GB/天量级，`saved/` **必须有清理机制**，否则 eMMC 撑不住。

## 决策

### 1. 留存时刻写入 `_saved_at`（真实时钟），时间轴不依赖文件名

`Store.save_pair()` 增加 `meta` 参数；采样器把 `_now_pair()` 的 `ts`（含 `M20AI_TS_OFFSET_SEC` 修正）写进留存 JSON 的 `_saved_at`，告警帧额外写 `_alert`。控制台「单帧检测」留存同理（偏移量取 Console 的 60s 缓存测量值）。

- 时间轴以 `_saved_at` 为排序/显示依据；
- 升级前的老文件没有该字段 → 退化为 `文件 mtime + 当前时钟偏移`（与 JSONL ts 同源，因为 mtime 也是同一本机时钟写的）；
- 只要成对文件在，`saved/` 就是**自描述**的（不依赖 results/ JSONL 是否被清理）。

### 2. 两个只读 API

- `GET /api/saved?n=1000&cam=`——汇总 `saved/<cam>/*.jpg`（成对 `.json` 补充 items/alert），按时间倒序，返回 `records[{cam,frame,ts,n_items,items,alert,url}]` + `cams/total/oldest/newest`；n 上限 5000；
- `GET /api/saved/img?cam=&frame=`——JPEG 二进制直出（`_safe_component` 防路径穿越；`Cache-Control: private, max-age=3600`——留存文件只写不改，可缓存）；
- 两者都是只读，不修改任何文件；单文件读取失败跳过（与清理竞态下属正常）。

### 3. 控制台新增"目标图片时间轴"卡片

页面在"服务控制 / 最近检测"之下新增全宽卡片（左图右控）：

- `<input type=range>` 时间条映射按时间排序的图片序列（**左=更早，右=更新**）；滑动即换图（数据已在内存，不发请求）；
- "跟随最新"默认开启（新图到达自动跳到最新）；**手动滑动自动暂停跟随**；
- 点图片 → 复用响应详情面板（saved 直读完整响应），滑块下方显示覆盖区间与位置（第 N / 共 M 张）；
- 相机多于一路时显示"全部/front/back"筛选 chips；页面每 15 s 轮询（页面隐藏时跳过）。

### 4. `saved/` 留存清理：`M20AI_SAVED_MAX_MB`（默认 500 / 0=不按体积清理）+ `M20AI_SAVED_KEEP_DAYS`（默认 0 / 0=不按年龄清理）

- `Store.clean_saved(max_bytes, keep_days)`：以 `(目录, stem)` 成对收集，先按年龄、再按总量上限，**从最旧开始成对删** `.jpg`+`.json`；单文件失败只记日志不中断（宁可漏删不可误删）；
- 采样器主循环每 **10 分钟**检查一次（`_maybe_prune_saved()`，与 `_maybe_prune_results()` 同范式；10 分钟粒度把超出上限的余量压在几十 MB 内）；
- 控制台留存卡可改（env 级，重启采样器后生效），与 ring/results 同一条 `POST /api/retention` 通道；
- 只删 `saved/`；`raw/`、`results/`、`alerts/` 不动。

### 5. 开机自启默认关闭（部署脚本不再 enable）

- `bootstrap.sh` / `console-bootstrap.sh` 不再 `systemctl enable`，**也不触碰既有状态**（曾 enable 过的保留）；安装完打印当前自启态与开启方法；
- helper 白名单新增 `svc-enable/svc-disable`、`console-enable/console-disable`（9→13 条，仍是精确完整命令行、无通配符）；
- `aiDetect` 新增 `enable|disable [--all]`（幂等：已是目标态则不调用）；`status` 增显示"开机自启 采样器 X · 控制台 Y"；
- 重启后的手动启动路径：**`aiDetect up --all`**（无 SSH 口令烦扰）。

## 依据

- ADR-004：系统时钟被车队 PTP 钉在 2024 → 一切"时间"必须经偏移修正；`_saved_at` 与 JSONL `ts` 同源同值（单测 `test_saved_json_carries_real_time` 断言相等）；
- ADR-006 复审条件①（"saved/ 出现 GB 级堆积 → 补环形配额或按天数清理"）在本 ADR 兑现；
- 磁盘核算（2026-10-16 实测：单对 ≈0.1 MB、检出率 96.2%、alert 命中率 3.4%）：`any` ≈ **7 GB/天**量级（几乎逐帧）、`alert` ≈ **0.3 GB/天**量级——默认 500 MB 上限 ⇒ 时间轴窗口 any ≈ 1~2 小时 / alert ≈ 1~2 天；上限、磁盘占用、可回看时长三者联动，页面提示里写明了换算；
- 提权面复核：enable/disable 与 start/stop 同级敏感度（只动自己两个 unit 的 systemd 状态、无自由参数），沿用 NOPASSWD 白名单模式；helper 全程 `logger -t m20-ai-console-helper` 留痕；
- 本地打桩验证：`aiDetect enable/disable` 幂等与 sudo 调用次序；`clean_saved` 成对删除/最旧优先/两维度各自生效/不碰其它目录；时间轴 API 排序、cam 过滤、ts 回退、路径穿越拒绝；页面 JS 经 node --check。

## 后果

### 正面

- 检出图片可按**真实时间**滑动回看，点图直达完整响应；数据源是自描述的 `saved/`，不依赖 results/ JSONL 的清理策略；
- `saved/` 变成有界目录：默认 500 MB，any/all 模式不会再打爆 eMMC；
- 部署后默认不自启，**重启控制权完全在用户手里**；`aiDetect up --all` 一键接管；
- 时间轴/清理全链路只读 + 单点写（采样器），控制台无需新增提权面。

### 负面 / 代价

- 时间轴可见范围 = **留存上限内的最新集合**（默认 500 MB：any ≈ 1~2 小时、alert ≈ 1~2 天），不是"永久图库"；这是磁盘有界的必然代价，已写进页面卡片提示；
- 升级前的老留存文件 ts 走 `mtime + offset` 近似（mtime 为写入时刻，与帧采集时刻最多差一个推理周期）；
- 采样器每 10 分钟多一次 `saved/` 目录遍历（数千文件 stat），量级可忽略；
- `/api/saved` 默认读最多 1000 个 json（≈ 250 KB 响应），页面 15 s 轮询一次——RK3588 上 CPU 占用 <1%，可接受；
- sudoers 白名单 9→13 条（提权面轻微扩大，均为固定命令行）。

### 触发复审的条件

- 时间轴窗口经常顶满、用户抱怨"看不到更早的" → 提高默认上限，或做分桶采样（稀疏历史 + 密集近期）；
- 出现"永久归档某类目标"需求 → 引入 pin/收藏（`clean_saved` 跳过 pinned 对）；
- `/api/saved` 慢到 >1 s → 增加写入侧索引（`saved/index.jsonl`，append-only），API 改读索引尾部；
- 多主机/多相机规模扩大后 15 s 轮询成为负担 → 增量拉取（`?since=`）+ ETag。

## 修订记录 2026-10-16（ADR-010）：`--all` 已移除，重启启动路径改写

正文中"重启后 `aiDetect up --all` 一键接管"与"`aiDetect` 新增 `enable|disable [--all]`"两处表述
已被 ADR-010 取代（提权模型与"部署后默认不自启"的结论不变）：

| 命令 | 现行语义 |
|---|---|
| `up` / `down` / `restart` | **只作用于控制台**（`m20-ai-console`，5050 网页） |
| `enable` / `disable` | **只作用于控制台**的开机自启；采集不设自启 |
| `collect on\|off\|status\|restart` | 采集开关（`m20-ai-detect`），默认关闭 |
| `--all` | **移除**；传参直接报错（不静默忽略） |

机器人重启后的手动启动路径：`aiDetect up`（开网页）→ 按需 `aiDetect collect on`（开采集）。
README §4.6、USAGE §0/§2.4/§5、ADR-007 均已同步；详细动机与设计见 ADR-010。
