# ADR-017: 身份与命名——app_id 一改，处处生效

- 日期：2026-10-19
- 状态：已接受（实施中，2026-10-19 T1–T8 已完成；见 §7 落地清单）
- 影响面：`src/m20_ai_detect/identity.py`、`src/m20_ai_detect/config.py`、`deploy/{identity.sh,render_env.py,render_units.py,env_upsert.py,migrate-rename.sh,aiDetect,site.env.example,profiles/,units/}`、`deploy/{bootstrap,console-bootstrap,install,install-local}.sh`、README、`docs/部署到新M20.md`
- 关联：ADR-016（通用视频源；§6 复审条件由 ADR-016 的"改名留到规模化时"触发）

## 背景

ADR-016 把「视频源」通用化之后，剩下的硬编码是**名字**：`m20` 被写死在 5 类地方——

| 层 | 写死的名字 | 换机型时的后果 |
|---|---|---|
| systemd | `m20-ai-detect.service` / `m20-ai-console.service` | Lite3/UGV 的机器上 unit 名不合身 |
| 提权入口 | `/usr/local/sbin/m20-ai-console-helper`、`/etc/sudoers.d/m20-ai-console` | sudoers 白名单与 helper 路径对不上，控制台按钮全废 |
| 配置文件 | `m20-ai-detect.env` / `m20-ai-console.env` | 多身份同机（m20 + lite3）必然撞名 |
| 日志 | `SyslogIdentifier=m20-ai-detect`、`/etc/logrotate.d/m20-ai-detect` | journal/logrotate 分不清是谁 |
| 展示 | UI 顶栏标题 | 用户看到"M20"实际跑的是别的平台 |

且改名成本被**鸡生蛋问题**放大：env 文件名依赖 app_id，而 app_id 又写在 env 文件里。此前换一台机器的标准动作是"手工改 unit 4 处 + env 2 处 + helper/sudoers 各 1 处 + 文档"，漏一处的表现是服务起不来或提权白名单悬空，且**没有任何测试能发现**（都是部署期产物）。

硬约束：

1. **104 上正跑着一份 m20 部署**（GOS 10.21.31.104，`/home/djw/m20-ai-detect`）——改造绝不允许让它多一个字的差异；
2. **部署脚本在目标机上以 bash 跑**——bash 侧必须有一份与 Python 侧逐条对齐的身份解析；
3. **`m20_ai_detect` 包名 / `M20AI_*` env 前缀不改**（import 路径与既有 env 是静态契约；对外的名字可配已足够）。

## 决策

> **引入 `app_id`（单一身份值），所有对外名字由它派生；缺省值 `m20` ⇒ 老部署零改动、字节级不变。**

### 1. 派生表（一次配置，处处生效）

| 名字 | 派生规则 |
|---|---|
| systemd unit | `<app_id>-ai-detect.service` / `<app_id>-ai-console.service` |
| root helper | `/usr/local/sbin/<app_id>-ai-console-helper` |
| sudoers 白名单 | `/etc/sudoers.d/<app_id>-ai-console` |
| 运行时 env | `<base>/<app_id>-ai-detect.env` / `<app_id>-ai-console.env` |
| journal 标识 | `SyslogIdentifier=<app_id>-ai-detect`、`logger -t <app_id>-ai-console-helper` |
| logrotate | `/etc/logrotate.d/<app_id>-ai-detect` |
| UI 展示名 | `M20AI_PLATFORM_NAME`（显式）> profile 展示名表 > `app_id` |

字符集 `^[A-Za-z0-9][A-Za-z0-9_-]{0,31}$`（对齐 systemd unit 名规则），非法值在**配置阶段**报错，而不是等 systemd 报 "Unit name is not valid"。

### 2. app_id 的来源（鸡生蛋问题的解法）

优先级从高到低：

1. `M20AIC_APP_ID`（控制台自身 env；install 渲染时写入）——控制台不需要读 detect env 就知道自己是谁；
2. 扫 `<base>/*-ai-detect.env`：文件内显式 `M20AI_APP_ID` > **文件名前缀**反查；
3. 都没有 → 缺省 `m20`。

第 2 条的文件名前缀反查是关键：老部署的 `m20-ai-detect.env` 里没有 `M20AI_APP_ID` 键，但文件名前缀就是 `m20`——**不改一个字也解析得出正确身份**。

### 3. 三层入口，一个缺省值

- **Python 运行时**：`m20_ai_detect.identity`（零依赖，不参与 Config 构造避免循环依赖）；
- **部署期 bash**：`deploy/identity.sh`（`detect_identity` / `render_units_into`，与 Python 侧同优先级、同字符集、同兜底）；
- **手工/CI**：`deploy/render_env.py` / `deploy/render_units.py`（`--app-id`）。

### 4. 缺省身份字节级不变（向后兼容的守护）

`app_id == "m20"` 时渲染器**一个身份键都不写**：env 文件内容、unit 内容与改造前逐字相同。由 `tests/fixtures/render_env_legacy.py`（改造前的渲染器复刻，只读快照）+ `test_default_identity_byte_identical_to_legacy`（detect/console × 3 种 site 全比对）守护——谁把缺省输出改花了，测试就红。

其余兼容手段：`Camera = Source` 别名、`M20AI_SOURCES` 缺省回落旧 `ENABLE_F/ENABLE_B`、`allow_local_device` 缺省 `False`、所有 `service=` 参数改 keyword-only。

## 落地清单（2026-10-19）

| 件 | 作用 |
|---|---|
| `src/m20_ai_detect/identity.py` | 运行时身份解析（`discover_app_id` / `Identity` / `scan_app_id`） |
| `deploy/identity.sh` | bash 侧同规则解析 + `render_units_into` 现场渲染 |
| `deploy/render_env.py` | env 渲染（`--app-id`；缺省身份不写键） |
| `deploy/render_units.py` | **四类产物**unit×2 / helper / sudoers 同表渲染（`--check` 防漂移，残留占位符 rc=4，漂移 rc=5） |
| `deploy/units/*.tmpl` | unit / helper / sudoers 模板（`@@APP_ID@@ @@BASE_DIR@@ @@RUN_USER@@ …`） |
| `deploy/env_upsert.py` | env 键级 upsert（迁移只改身份派生键，用户键不碰） |

## 改名的影响清单（app_id 一改，下列全部自动跟随）

unit×2、helper、sudoers、env×2、`M20AIC_ENV_FILE`/`M20AIC_HELPER`/`M20AIC_APP_ID`（console env 内）、journald `SyslogIdentifier`、logrotate conf、`logger -t` 标识。**手工不需要改任何东西**；`migrate-rename.sh --apply --switch` 之外的选择是重装（bootstrap 系列脚本全部身份化，本来就按 app_id 装）。

### 已知边界

- **包名 / env 前缀不变**（静态契约，见背景约束 3）；
- **`aiDetect` 的 BASE 探测**仍从默认路径 `/home/djw/m20-ai-detect/m20-ai-detect.env` 读 `M20AI_BASE_DIR`——非默认 BASE 需设 `M20AI_BASE_DIR`（改造前即如此，未新增限制）；
- **Windows/Git Bash 开发机上跑 deploy 脚本**：`MSYS_NO_PATHCONV=1` + `cygpath -w` 双管齐下防 MSYS 把 `/usr/local/sbin/...` 形式的**值**污染成 `C:/Program Files/Git/...`（2026-10-19 实测踩到，`migrate-rename.sh` 与 `render_units_into` 已加固；目标机 Linux 无此行为）。

## 后果

### 正面

- 换平台（Lite3/IPC/UGV）= 改 `deploy/site.env` 的 `APP_ID` + 挑一个 profile，其余全自动；
- 同机多身份（m20 + lite3 + ipc 并存）不再撞名，互不干扰；
- 缺省身份零变化 ⇒ 104 上的老部署继续跑，无需重装；
- 漂移可检测：`render_units.py --check` 进 CI，模板与成品不许脱节。

### 负面 / 代价

- **两套解析**（Python + bash）必须同步改——靠 `identity.sh` 的注释逐条对齐约定与 `test_identity.py` 的字符集用例缓解，没有自动一致性检查；
- 新增一类测试（字节级快照）需要维护 `tests/fixtures/render_env_legacy.py`；
- `M20AIC_*`/`M20AI_*` 两套 env 前缀并存， newcomers 容易看晕。

### 触发复审的条件

1. 要改包名 `m20_ai_detect` 或 env 前缀 `M20AI_*`（意味着 import/契约层重构，一次性大工程）；
2. 出现"同 app_id 多副本同机"的真实需求（当前语义是一机一身份，多副本要靠不同 app_id 区分，可能不敷使用）；
3. `migrate-rename.sh` 的需求收敛后，可考虑把它退化成一个 `aiDetect rename` 子命令（收敛入口）。
