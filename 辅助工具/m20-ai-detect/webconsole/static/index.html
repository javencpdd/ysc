日志与数据留存策略

      

        
journal 日志 —— systemd 服务运行日志（「运行日志」卡的来源）

        

          

          
          

          
          

          
一次性动作，不是持续配置：从最旧的日志开始删，删到满足限额即止（二选一），执行后 journal 仍会继续增长；作用于整机所有单元的 journal，不止本服务。
单位：体积默认 MB（200=200MB），可写 K/M/G/T；时长默认天（7=7天），可写 s/m/h/d/w。

        

        

          
          
          
          
          

          
写入 /etc/systemd/journald.conf，长期生效（重启后仍有效）。想“永远只留最近 200M / 7 天”，用这里，而不是上面的立即清理。
单位：与左侧相同（体积默认 MB、时长默认天，均可带 K/M/G/T 与 s/m/h/d/w）。

        

        

          
          
          

          
单位：份（整数 1–365，无单位后缀），每份=一天的日志文件。只作用于 log/*.log 文件日志（不影响 journal）：每天切一份、保留最近 7 份（≈ 最近 7 天）、旧份 gzip 压缩、超出 7 份的最旧自动删除。

        

        
检测数据与图片 —— saved/ 留存图、raw/ 原始帧、results/ 记录、spool/ 积压

        

          
① 留存条件 —— 什么样的帧才配存图

          
          
          
只决定一帧够不够格进 saved/：off = 只写 JSONL；alert = 仅命中「关注目标」的帧（清单在「关注目标」卡，为空 = 不保存）；any = 检出任意目标；all = 每帧。
raw/、results/ 与此无关：无论选哪一项，原始帧和检测记录都照常保存（那是下面 ② 的容量与时长在管）。

          


          
② 容量与时长 —— 各目录最多留多少 / 留多久

          
          
          
          
          
          
          
          
          
只决定“最多留多少 / 留多久”，与上面的准入条件正交：raw/ 超上限挤最旧帧、results/ 超期整文件删、saved/ 按年龄 + 总量成对删。四个框对应四个互不相干的维度（raw 容量 / results 天数 / saved 容量 / saved 天数），改一个不影响其它三个。

          

          
单位（四个数值框通用）：体积类（ring/saved 上限）默认 MB，可写 200 / 200M / 1G；时长类（keep/days）默认天，可写 7 / 7d / 24h / 2w。带不带单位都行，非法单位会明确报错。
清理节奏：raw/ 每轮检查（挤最旧帧）、saved/ 每 10 分钟（成对删）、results/ 每小时（整文件删）。
磁盘参考（1 路 1fps，单对 ≈0.1MB，实测）：any ≈7GB/天（检出率高时几乎逐帧 → 500MB ≈ 最近 1~2 小时）；alert ≈0.3GB/天（视命中率 → 500MB ≈ 1~2 天）。想回看更久就调大上限（注意磁盘余量）。

        

        

          
          
          
          
          
          
流程：停采集（仅当运行中）→ 删除所选 → 恢复采集原状态（采集原本关着就不会被拉起）。清 results/ 会重置「最近检测」与今日统计；清 saved/ 会清空时间轴。
