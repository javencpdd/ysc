## 0·5 先分清三种「建图」（极易混淆）

| # | 名字 | 谁提供 | 干什么 | 能存档吗 |
|---|---|---|---|---|
| **A** | **实时局部占据栅格** | **SCAN-Planner 自带**（`plan_env/grid_map.cpp` + `raycast.cpp`） | 给规划器避障用：滑动窗口 `10×10×5 m`、分辨率 `0.05 m`，输入世界系点云 + 里程计，输出 `/grid_map/occupancy`、`occupancy_inflate` | ❌ 不存档，随机器人滑动 |
| **B** | **全局点云建图（SLAM）** | **FAST-LIO**（在 `lite_cog/slam`，**不属于 scan_planner**） | 算位姿（`/Odometry`）并累积点云，退出时写 PCD | ✅ 存档为 `.pcd` |
| **C** | 仿真地图生成 | SCAN-Planner 的 `simulator/map_generator`、`mockamap` | 仿真里随机生成障碍物地图 | 仅仿真 |

**所以：SCAN-Planner 有建图代码（A），但它是"给规划器自己看的局部地图"，
不是能存下来当全局底图的 SLAM。** 想要全局地图（给 Nav2 / Foxglove / 多机协同），必须走 B（FAST-LIO + pcd2grid）。

二者关系：

```text
FAST-LIO(B) ──/Odometry──┐
                          ├──> grid_map(A) ──> SCAN-Planner 规划避障
雷达点云 ──/cloud_registered─┘
     │
     └──> scans.pcd ──copy──> map/lite3.pcd ──pcd2grid──> /map(全局栅格) ──> Nav2/协同
```

> SCAN-Planner 本身**不做定位也不做全局一致化**，它必须吃外部里程计（我们用的是 FAST-LIO 的 `/Odometry`，
> 经 `lio_relay.launch` 转成 `/LIO/odom_vehicle`）。这也是为什么"建图"这一环必须靠 FAST-LIO。

## 2. 建图五步（可直接复制）

### 步骤 1：准备（腾出 CPU / 内存）

```bash
# 建图期间不需要规划器，先停掉（省 CPU，也避免它刷日志）
cd /home/test/scan_planner && bash scripts/stop_all.sh

# 确认 SLAM 在跑（建图主体）
ps -eo comm | grep laserMapping
source scripts/env.sh && timeout 6 rostopic hz /Odometry
```

> ⚠️ pcd2grid 要吃内存（1.1 GB 的 PCD），103 只有 6.7 GiB。
> **跑 pcd2grid 时务必先停规划器与 SLAM**，否则可能 OOM 把 103 拖死。

### 步骤 2：走一圈（遥控，慢速）

**用手柄遥控狗慢速走**，覆盖你想建的区域：

- 速度 **0.3~0.5 m/s**，转弯放慢（FAST-LIO 对快速旋转敏感）
- **尽量走闭环**（回到起点），能显著提高全局一致性
- ❌ **不要搬动狗** —— 起 SLAM 后搬动会导致 LIO 发散（坐标跑到百万米级，见避坑第 17/24 章）
- 不要长时间原地不动（点云会持续堆，PCD 迅速膨胀）

### 步骤 3：停止 SLAM，让它保存 PCD

```bash
# 优雅停止（不要 kill -9，否则不会触发保存）
pkill -f "mapping_c16.laun[c]h"
sleep 5
ls -la /home/ysc/lite_cog/slam/src/faster-lio/PCD/scans.pcd
```

> ⚠️ 分两步执行：`pkill` 的命令里**不要**同时出现 `run.launch` 等其它启动串，
> 否则 `pkill -f` 会匹配到发起命令的 shell 自己（exit 255，见避坑 5.1 / 第 24 章末尾）。

### 步骤 4~5：收图 + 转栅格 + 存档（用封装脚本，产物全进 `scan_planner/map/`）

```bash
cd /home/test/scan_planner

# 4. 把 SLAM 刚存的 scans.pcd 收进来（旧图自动加时间戳备份）
bash scripts/build_map.sh copy

# 5a. PCD -> 栅格（读 map/lite3.pcd，发布 /map）；前台跑，Ctrl+C 停
bash scripts/build_map.sh grid

# 5b. 另开一个终端：存档
bash scripts/build_map.sh save      # -> map/lite3.yaml + map/lite3.pgm

# 随时可查 PCD 是否有效
bash scripts/build_map.sh check
```

产物全部在 **`/home/test/scan_planner/map/`**：

```text
map/
├── lite3.pcd              # 当前点云底图（pcd2grid 输入）
├── lite3_<时间戳>.pcd     # 每次 copy 时的旧图备份
├── lite3.yaml             # 栅格地图（Nav2 / Foxglove 可直接加载）
└── lite3.pgm
```

> 原路径 `/home/ysc/lite_cog/system/map/lite3.pcd` 已改为**软链接**指向这里，
> 老脚本（`save_map.sh` 等）不会失效，但实际文件只存一份。

## 3. pcd2grid 的关键参数（`pcd2grid.launch`）

| 参数 | 当前值 | 含义 / 调法 |
|---|---|---|
| `file_path` | `/home/ysc/lite_cog/system/map/lite3.pcd` | 输入 PCD，改文件名即换图 |
| `filter_leaf_size_m` | `0.05` | 降采样体素边长；**PCD 太大时调大**（0.1 / 0.2）以加速 |
| `frame_id` | `/map` | 输出栅格的坐标系 |
| `pointcloud_min_z / max_z` | `0.4 / 1.2` | **只保留这个高度带的点**（Lite3 站立时雷达约在此高度） |
| `occupancy_min_z / max_z` | `0.0 / 1.6` | 判定占据的高度区间 |

> 若建图时狗是趴着的/高度不同，`pointcloud_min_z/max_z` 要跟着改，否则会生成空地图。

## 4. PCD 太大的问题（重要）

现象：单次建图 10 分钟 → **3480 万点 / 1.1 GB**。原因在 `c16.yaml`：

```yaml
pcd_save:
    pcd_save_en: true
    interval: -1     # -1 = 所有帧存进同一个 PCD，注释里明确警告可能内存崩溃
```

三条对策（按推荐度）：

1. **限时建图**：只跑必要的路线，走完立刻停 SLAM 保存（最简单）
2. **调大 `filter_leaf_size_m`**：pcd2grid 降采样更狠，处理更快
3. **分批保存**：把 `interval` 改成正数（如 `100`），每 N 帧存一个文件，避免单文件过大

另外：不建图时可以把 `pcd_save_en` 设回 `false`，避免 SLAM 一直堆点。

# PCD 是否有效（看坐标范围，出现百万米级 = 发散，要重跑）
python3 - <<'PY'
import struct
p="/home/ysc/lite_cog/system/map/lite3.pcd"
f=open(p,"rb"); hdr=[]
while True:
    l=f.readline().decode("ascii","ignore").strip(); hdr.append(l)
    if l.startswith("DATA"): break
off=f.tell(); n=int([h for h in hdr if h.startswith("POINTS")][0].split()[1])
xs=[];ys=[];zs=[]
for i in range(0,n,max(1,n//3000)):
    f.seek(off+i*16); b=f.read(16)
    if len(b)<16: break

print("点数 %d | x %.1f~%.1f | y %.1f~%.1f | z %.1f~%.1f"%(n,min(xs),max(xs),min(ys),max(ys),min(zs),max(zs)))
PY

# 栅格是否生成
ls -la /home/ysc/lite_cog/system/map/lite3.yaml /home/ysc/lite_cog/system/map/lite3.pgm
