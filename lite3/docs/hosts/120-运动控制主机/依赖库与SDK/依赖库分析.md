## 4. 上下游依赖

`qirui` 的命名及库集合显示它可能是历史开发/部署时复制的一组通用依赖。它与 `jy_exe/lib`、`Lite3_MotionSDK`、`sdk_lib` 中可见依赖类别有重合，但本次未发现当前运行服务把 `qirui/lib` 显式加入 `LD_LIBRARY_PATH` 或作为工作目录。

这只能说明它**当前没有直接入口证据**，不能证明任何程序绝不会通过其他动态链接器配置加载其中的库。

## 5. 风险与维护边界

1. 不要把 `lib.zip` 直接解压覆盖 `lib/`；不同 ARM、OS、glibc、RKNN 或 EtherCAT 版本可能不兼容。
2. 没有服务引用时，不应为“清理空间”删除该目录；它可能是离线恢复或编译依赖来源。
3. 若未来某程序需使用它，应显式记录 `LD_LIBRARY_PATH`、库版本与 CPU 架构，避免与 `jy_exe/lib` 的同名库混用。
