# 主机控制与环境脚本

## 目录定位与职责

本文件覆盖 `/home/ysc/Wifi.sh`、`/home/ysc/.ros_version.sh` 与 `/home/ysc/scripts`。它们不实现机器人算法，却决定网络可用性、ROS 运行时和两套服务的选择。

## 脚本清单

### `Wifi.sh`

| 项目 | 说明 |
| --- | --- |
| 启动方式 | `bash /home/ysc/Wifi.sh`；无位置参数。 |
| 可覆盖变量 | `BAIDU_HOST`、`PUBLIC_IP`、`DNS_SERVERS`、`NM_CONF`、`WIFI_IFACE`、`AUTO_REBOOT`。 |
| 执行流程 | 检查 sudo 与 `nmcli/ip/ping/awk/python3`；清理 NetworkManager 中的 `unmanaged-devices`；选择 Wi-Fi 网卡；扫描并交互选择 SSID；连接；测试域名与公网 IP；必要时修默认路由与 DNS。 |
| 调用场景 | 机器人需要通过 `p2p0` 或 `wlan0` 联网、且 NetworkManager 未接管网卡或路由/DNS 异常时。 |

`WIFI_IFACE=wlan0 bash Wifi.sh` 可指定网卡；脚本明确提示这可能中断 AP 热点。若 `AUTO_REBOOT=1`，它会在修 NetworkManager 配置后直接重启系统。

### `.ros_version.sh`

当前配置为 ROS 2 Foxy：source Foxy、colcon 辅助脚本，设置 `ROS_DOMAIN_ID=0`、`ROS_LOG_DIR=/home/ysc/lite_cog_ros2/system/log` 与 Cyclone DDS。`~/.bashrc` 会自动 source 该文件，并另行导出 `ROS_MASTER_URI=http://192.168.1.103:11311` 与 `ROS_HOSTNAME=192.168.1.103`。

### `scripts/print_ros_version.sh`

需要 root。通过 `systemctl is-enabled transfer` 判断模式：`transfer.service` enabled 则打印 ROS 1，否则打印 ROS 2。它不检查 `transfer_ros2.service`，因此只是约定式检测，不是完整状态诊断。

### `scripts/switch_ros_version.sh`

| 参数 | 行为 |
| --- | --- |
| `ros1` | 覆盖 `.ros_version.sh` 为 Noetic 环境；停用 ROS 2 transfer；重启并启用 `transfer.service`。 |
| `ros2` | 覆盖 `.ros_version.sh` 为 Foxy/Cyclone DDS 环境；停用 ROS 1 transfer；重启并启用 `transfer_ros2.service`。 |

脚本要求恰好一个参数且必须以 root 运行。它是 ROS 工作区切换的上游入口，影响后续所有终端和服务。

## 上下游依赖

- 上游：系统 ROS 安装、systemd、sudo 权限、NetworkManager。
- 下游：`lite_cog` / `lite_cog_ros2` 的所有 `roslaunch`/`ros2 launch` 进程，特别是两代 transfer 服务。

## 风险与硬编码

1. **高风险网络改动**：`Wifi.sh` 会删除其他默认路由、修改连接 DNS、重启 NetworkManager，并可重启主机。应在本地控制台执行，不应在正在依赖该网络的远程会话中盲目运行。
2. **覆盖式配置**：版本切换脚本用重定向完整覆盖 `.ros_version.sh`，手工追加的环境变量会丢失。
3. **硬编码地址**：`.bashrc` 固定本机 IP；DHCP 变更或主机迁移时，ROS 通信会异常。
4. **服务选择不完整**：`print_ros_version.sh` 以 ROS 1 服务是否 enabled 作二元判断，无法反映两个服务都被禁用、或 service 启动失败的情况。
