# 总体分析：`/home/ysc`

## 1. 整体目录与职责

`/home/ysc` 的工程核心是两套并行的机器人软件栈：

```text
硬件相机/激光雷达
  -> 驱动工作区（driver(s)）
  -> ROS 1: lite_cog        或  ROS 2: lite_cog_ros2
      -> transfer：底盘、IMU、遥控器、传感器状态 UDP/ROS 桥接
      -> slam：激光惯导建图、点云转占据栅格、地图保存
      -> nav：地图加载、点云定位、导航规划
      -> voa：深度点云高度图、避障速度修正
      -> track：YOLO 人体跟踪，发布/转发跟随速度
```

| 目录 | 角色 | 备注 |
| --- | --- | --- |
| `lite_cog` | ROS 1/Noetic 主工作区 | 以 `devel/setup.bash` 与 `roslaunch` 运行。 |
| `lite_cog_ros2` | ROS 2/Foxy 主工作区 | 以 `install/setup.bash` 与 `ros2 launch` 运行。 |
| `scripts` | ROS 版本识别/切换 | 控制两代 transfer systemd 服务。 |
| `Wifi.sh` | Wi-Fi 接入、路由与 DNS 修复 | 会修改系统网络配置，见风险说明。 |
| `.ros_version.sh` | 登录 shell 的 ROS 环境片段 | 当前内容为 Foxy/Cyclone DDS，即 ROS 2 模式。 |
| `Documents/lib`、`.local` 等 | 用户资料或第三方库/运行环境 | 不属于机器人主流程源码。 |

## 2. 实际运行入口

`~/.bashrc` 会 source `~/.ros_version.sh`，并固定导出 `ROS_MASTER_URI`、`ROS_HOSTNAME` 为 `192.168.1.103`。当前 `.ros_version.sh` source `/opt/ros/foxy/setup.bash`，设置 `ROS_DOMAIN_ID=0`、`RMW_IMPLEMENTATION=rmw_cyclonedds_cpp` 和 ROS 2 日志目录。

`scripts/switch_ros_version.sh ros1|ros2` 是模式切换入口：它覆盖 `.ros_version.sh`，并在 `transfer.service`（ROS 1）与 `transfer_ros2.service`（ROS 2）之间 stop/disable 与 restart/enable。调查时的有效状态是：

- `transfer_ros2.service`：enabled 且 active；
- `transfer.service`、`nav.service`、`track.service`、`voa.service`、`voa_ros2.service`：disabled 且 inactive。

因此当前主路径是 ROS 2 transfer；导航、建图、驱动和 VOA 多数仍需人工执行对应系统脚本或手工启动服务。

## 3. 模块间依赖与调用关系

### ROS 1

```text
start_lslidar.sh / start_livox.sh / 相机脚本
  -> 点云、IMU、图像话题
  -> faster_lio 或 hdl_localization
      -> map、TF、/odom、move_base
          -> pipeline Task.py（MoveBaseAction）
          -> message_transformer（/cmd_vel 与底盘 UDP）
          -> deeprobotics_local_height_map（高度图/安全控制）
          -> track（YOLO 目标跟随速度）
```

### ROS 2

```text
driver/*/start_*.sh
  -> /rslidar_points、/imu/data、深度点云
  -> hdl_localization（/odom、/aligned_points、/status）+ Nav2
  -> transfer/jetson2motion（腿式里程计、IMU、/cmd_vel 转 UDP）
  -> voa_composition（点云 -> grid_map -> /cmd_vel_corrected）
  -> transfer/jetson2motion 订阅修正后的速度并转发到运动控制端
```

## 4. 运行入口清单

| 场景 | ROS 1 | ROS 2 |
| --- | --- | --- |
| 版本切换 | `sudo scripts/switch_ros_version.sh ros1` | `sudo scripts/switch_ros_version.sh ros2` |
| 运动/传感器桥接 | `systemctl start transfer.service` 或 `start_transfer.sh` | `systemctl start transfer_ros2.service` 或 `start_transfer.sh` |
| 雷达 | `system/scripts/lidar/start_lslidar.sh` 或 `start_livox.sh` | 同名 ROS 2 系统脚本 |
| 相机 | Orbbec / RealSense 启动脚本 | RealSense 启动脚本 |
| 定位导航 | `start_nav.sh` | `system/scripts/nav/start_nav.sh` |
| 建图 | `start_slam.sh` | `system/scripts/slam/start_slam.sh` |
| VOA | `start_voa.sh` | `system/scripts/voa/start_voa.sh` |

## 5. 全局风险与配置耦合

1. **ROS 双栈互斥服务**：版本切换脚本不是同时运行两套，而是切换 transfer 服务；在错误的 shell 环境中启动脚本会混用 ROS 1/ROS 2。
2. **机器绑定路径与地址**：大量 launch/script 固定 `/home/ysc/lite_cog*`、`192.168.1.103` 或运动控制端 `192.168.1.120`；迁移主机或更换网络必须同步更新。
3. **地图文件是跨模块契约**：定位与导航读取 `system/map/lite3.yaml` 与 `lite3.pcd`；ROS 2 建图保存又会写同名地图文件。文件缺失或版本不匹配会使定位/导航失败。
4. **图形界面依赖**：两代 `start_slam.sh` 使用 `gnome-terminal`，视觉跟踪使用 OpenCV 窗口；均不适合无图形/纯 systemd 环境。
5. **已有断链入口**：`track.service` 指向 `/home/ysc/lite_cog/system/scripts/track/start_track.sh`，该文件不存在，启动服务必然失败。
6. **启动脚本健壮性不一致**：多数系统脚本没有 `set -e`、参数校验、进程 PID 管理或互斥检查；后台 `&` 使 systemd 的 `Type=forking` 难以精确追踪子进程。
