# ROS 1：传输、避障与视觉跟踪

## 目录定位与职责

- `transfer/src/message_transformer`：ROS 与机器人运动控制/应用端之间的 UDP 消息桥接、传感器健康检查。
- `voa/src/deeprobotics_local_height_map`：由深度/点云和机器人姿态生成局部高度图，并提供安全控制链路。
- `track`：YOLO + GStreamer 的人员跟踪与跟随速度生成。

## Transfer

`system/scripts/transfer/start_transfer.sh` 无参数：source `transfer/devel/setup.bash` 后后台运行 `roslaunch message_transformer message_transformer.launch`。它也是 `transfer.service` 的入口；当前该服务 disabled/inactive。

launch 同时启动：

- `qnx2ros`：服务端端口 `43897`，并发布 IMU；
- `ros2qnx`：向 `192.168.1.120:43893` 发运动指令，本地端口 `43894`；
- `nx2app`：应用端服务端口 `43899`；
- `sensor_checker`：按 2 Hz 检查 IMU、两类里程计、关节、RealSense、雷达、超声，静默阈值多为 3。

维护脚本均需 sudo：`start.sh`/`stop.sh` 控制 `transfer.service`，`status.sh` 显示状态，`log.sh` 跟随 journal。它们不接收位置参数。

## VOA

`system/scripts/voa/start_voa.sh` 无参数，source `voa/devel/setup.bash` 后后台启动 `deeprobotics_local_height_map height_map_lite.launch`。核心包依赖 PCL、grid_map、TF、传感器/里程计消息；launch 可按相机姿态选择高度图配置，并可选启动安全节点、平面分割、地形图传输、URDF 与 RViz。

默认 `height_map_lite.launch` 采用 `camera_pose=horizontal`、启用 safety、关闭 gridmap transformer 与四边形约束。其下游安全节点可根据高度图/障碍物修改运动链路；上游需要相机点云与 TF。

## Track

`track/model/export_engine.sh` 无参数，运行：`yolo export model=yolov8n.pt format=engine half=True simplify=True`，用于生成 TensorRT engine。`track/src/test/pull.sh` 无参数，使用 GStreamer 拉取 `rtsp://192.168.1.120:8554/test`，依赖 NVIDIA `nvv4l2decoder`/`nvvidconv`。

实际入口是 Python `src/run_tracker.py`，不是 shell 脚本：GStreamer 取帧 -> Ultralytics YOLO 目标跟踪 -> OpenCV 界面输入目标 ID -> `RobotController` 计算线速度/角速度 -> ROS 1 Transfer 发布。按 Enter 选择/重置目标；它依赖图形窗口和视频流。

## 风险与硬编码

1. **UDP 固定地址端口**：Transfer 与 Track 都依赖 `192.168.1.120` 及 `43893/43894/43897/43899`。
2. **断裂的服务入口**：`track.service` 指向不存在的 `system/scripts/track/start_track.sh`，因此不能作为 Track 的可用启动方式。
3. **运动安全链路**：Track 产生的跟随速度若绕过 VOA 安全修正，会增加碰撞风险；启动顺序和话题连通性须在实机前验证。
4. **硬件/图形依赖**：YOLO engine 导出依赖模型、TensorRT/GPU；RTSP 拉流依赖 Jetson/GStreamer 插件；Tracker 需要 DISPLAY。
5. **第三方组件**：`track/src/ultralytics`、`hub_sdk`、VOA 的 `libraries/kindr*` 与模型目录按规则未递归展开。
