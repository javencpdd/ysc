# ROS 1：导航与任务管线

## 目录定位与职责

- `lite_cog/nav`：点云定位和 ROS 1 导航栈集成。
- `lite_cog/pipeline/src/pipeline_tracking`：自定义巡航任务状态机，通过 `move_base` Action 和底盘 UDP 指令完成路线巡航。

## 运行入口

`system/scripts/nav/start_nav.sh` 无参数，source `nav/devel/setup.bash` 后执行：

```text
roslaunch hdl_localization local_rslidar_imu.launch
```

它也是 `nav.service` 的 `ExecStart`。调查时该服务 disabled/inactive，因此不会自动运行。

## 定位与导航流程

`local_rslidar_imu.launch` 的运行链路是：

```text
/rslidar_points + /imu/data
  -> HdlLocalizationNodelet（NDT_OMP 匹配）
  -> /odom、map TF、/aligned_points、定位状态
  -> include navigation/launch/navigation.launch
  -> move_base Action 服务
  -> pipeline TaskTransfer 发送目标点
```

关键参数：`map_name=lite3`，读取 `/home/ysc/lite_cog/system/map/lite3.yaml` 和 `lite3.pcd`；`odom_child_frame_id=base_link`；启用 IMU；初始位姿固定为原点单位四元数；NDT 使用 `DIRECT1`、分辨率 `2.0`、下采样 `1.0`。`hdl_global_localization` 是可选全局重定位包，通过独立 launch 加载 BBS/FPFH/RANSAC/TEASER 配置。

## 任务管线模块

| 文件 | 职责 |
| --- | --- |
| `Task.py` | 主入口。读取 `../data/*.json` 路点，按 `order` 排序，选最近点并循环发送导航目标、切步态。 |
| `TaskPoint.py` | 封装路点位姿、步态选项、欧氏距离与前驱路点。 |
| `TaskTransfer.py` | `SimpleActionClient("move_base")`；以 `map` 坐标系发送 `MoveBaseGoal`，5 秒等待后若未成功无限重试。 |
| `RobotCommander.py` | UDP 控制端。绑定本地 `20001`，向 `192.168.1.120:43893` 每 0.25 秒发送心跳和步态/速度二进制协议。 |
| `dyn_reconfigure.py` | 直接修改 TEB 限速参数，并禁用本地/全局 costmap 的两层障碍物层。 |
| `tools/location_record*.py` | 路点录制辅助工具；用于生成任务数据。 |

`pipeline` 会生成自定义 `MoveBase.action`，但实际依赖名为 `move_base` 的 Action 服务。它连接的上游是定位/导航；下游是底盘控制端和路点 JSON。

## 第三方边界

`fast_gicp`、`move_base`、`navigation`、`ndt_omp`、`teb_local_planner` 是上游导航/配准组件，仅记录用途，不递归展开。`hdl_localization` 与 `hdl_global_localization` 在本工程中承载配置与集成，已分析其 launch 级接口。

## 风险与硬编码

1. **地图强绑定**：`lite3.yaml` 与 `lite3.pcd` 固定路径，二者缺一不可。
2. **底盘地址硬编码**：任务管线固化控制端 `192.168.1.120:43893` 和本地端口 `20001`。
3. **无限重试**：`TaskTransfer` 对 Action 不成功持续重发，可能在障碍、定位失效或导航服务未启动时持续占用控制链路。
4. **动态禁用避障层**：`dyn_reconfigure.py` 禁用四个 costmap obstacle layer，执行前必须明确其安全影响。
5. **初始位姿假设**：launch 默认把定位起点固定为原点；地图与机器人实际起点不一致会导致导航失效。
