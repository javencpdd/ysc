# ROS 1：传感器驱动与系统启动

## 目录定位与职责

ROS 1 主工作区是 `/home/ysc/lite_cog`。可人工执行的系统启动器位于 `system/scripts`；实际驱动代码位于 `drivers/*`，属于厂商 SDK 或上游 ROS 驱动工作区，按规则不递归展开。

## 启动脚本清单

| 脚本 | 参数 | 执行流程与用途 | 主要依赖 |
| --- | --- | --- | --- |
| `depth_camera/orbbec/start_orbbec.sh` | 无 | `cd` 到 `drivers/orbbec_ws`，source `devel/setup.bash`，后台执行 `roslaunch orbbec_camera dr-gemini2.launch`。 | Orbbec ROS 驱动、Gemini2 设备。 |
| `depth_camera/realsense/start_realsense.sh` | 无 | source `drivers/realsense_ws/devel/setup.bash`，后台执行 `realsense2_camera dr_camera.launch`。 | RealSense ROS 驱动。 |
| `lidar/start_livox.sh` | 无 | source `drivers/mid360_ws/devel/setup.bash`，前台执行 `livox_ros_driver2 msg_MID360s.launch`。 | Livox Mid-360 驱动。 |
| `lidar/start_lslidar.sh` | 无 | source `drivers/leishen_ws/devel/setup.bash`，前台执行 `lslidar_driver lslidar_c16.launch`。 | Leishen C16 驱动。 |

这些脚本是雷达/相机到 ROS 话题的最上游入口。ROS 1 导航默认选择 `/rslidar_points` 和 `/imu/data`，因此实际雷达 launch 的话题名称必须与定位 launch 匹配。

## 驱动目录与调用关系

```text
system/scripts/depth_camera/* -> drivers/orbbec_ws 或 drivers/realsense_ws
system/scripts/lidar/start_livox.sh -> drivers/mid360_ws -> livox_ros_driver2
system/scripts/lidar/start_lslidar.sh -> drivers/leishen_ws -> lslidar_driver
导航/SLAM/VOA -> 消费驱动发布的点云、IMU、图像或深度点云
```

`drivers/Livox_SDK2` 是 Livox 原生 SDK；四个 `*_ws` 是各厂商 ROS 工作区。它们的 `devel` 子目录包含 Catkin 自动生成环境脚本，不作为手写启动逻辑分析。

## 运行场景

- 建图/定位前先选择并启动一套雷达；`start_lslidar.sh` 对应 C16，`start_livox.sh` 对应 MID360s。
- 深度相机是 VOA 或视觉相关功能的上游。相机脚本以 `&` 返回，调用者必须自行观察 launch 是否成功。
- `nav.service` 的启动脚本仅启动导航，不自动启动传感器驱动；操作顺序需要人工保证。

## 风险与硬编码

1. **固定工作区**：所有脚本都固定 `/home/ysc/lite_cog/drivers/...`，复制工程后不能直接复用。
2. **无失败处理**：未使用 `set -e`，source 失败时可能继续执行并产生难以理解的 `roslaunch` 错误。
3. **后台进程不可追踪**：两类相机使用 `&`，没有 PID 文件、健康检查或重启策略。
4. **话题契约风险**：导航 launch 期望 `/rslidar_points`；切换为 Livox/其他驱动前必须核实话题重映射。
