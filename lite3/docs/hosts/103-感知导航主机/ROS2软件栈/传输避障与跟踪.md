# ROS 2：传输、避障与视觉跟踪

## 目录定位与职责

- `transfer/src/transfer`：ROS 2 到运动控制端/应用端的 UDP 桥接和传感器保活。
- `transfer/src/transfer_interfaces`：桥接使用的自定义 ROS 接口包。
- `voa/src/voa`：点云预处理、栅格地图和安全速度修正。
- `track`：与 ROS 1 同源的 YOLO 跟踪程序，但选择 ROS 2 Transfer。

## Transfer 脚本、节点与数据流

`system/scripts/transfer/start_transfer.sh` 无参数：设置 Foxy、Cyclone DDS、日志目录，source `transfer/install/setup.bash` 后后台启动 `transfer_launch.py`。它由当前 active 的 `transfer_ros2.service` 调用。

| 节点 | 主要作用 | 关键参数/接口 |
| --- | --- | --- |
| `jetson2app` | 接收应用侧 UDP 并转 ROS 消息 | 本地端口 `43899`；写 `transfer/nx2app_log.txt`；发布 `commands/joy_raw`。 |
| `jetson2motion` | 运动状态 UDP->ROS，ROS 速度->运动控制 UDP | 本地 `43897`，目标 `192.168.1.120:43893`；发布 `leg_odom`、`leg_odom2`、`joint_states`、`/imu/data`、超声和手柄状态；订阅 `cmd_vel`、`cmd_vel_corrected` 与自定义运动指令。 |
| `sensor_checker` | 订阅关键传感器并发布 `sensor_status/*_isalive` | launch 中 `is_debug=True`。 |

这使得 `cmd_vel_corrected` 成为 VOA 对运动控制链路的关键下游接口。

## VOA

`voa_launch.py` 提供一个 `config_path` launch 参数，默认包内 `config/voa.yaml`；启动静态 `base_link -> camera_link` TF 和 `voa_composition`。`debug_launch.py` 额外启动假 IMU 和 RViz。

模块内部数据流：

```text
/camera/depth/color/points + /imu/data
  -> PointCloudProcessor
  -> /camera/depth/color/transformed_points
  -> GridMapper
  -> grid_map
  -> SafetyController（同时消费超声、leg_odom2、/cmd_vel、/handle_state）
  -> /cmd_vel_corrected + MarkerArray
  -> transfer/jetson2motion
```

默认参数涉及高度图尺寸 `6 x 4`、分辨率 `0.05`、CUDA 开启、点云通道、膨胀/腐蚀和避障安全阈值。它依赖 PCL、OpenCV 与 `grid_map_*` 组件。

## 视觉跟踪

`track/model/export_engine.sh` 与 `src/test/pull.sh` 和 ROS 1 版本一致：分别导出 YOLOv8n TensorRT engine、从固定 RTSP 地址拉流。`run_tracker.py` 是实际程序入口；ROS 2 副本将 `kUseRos1Transfer=False`，故经 ROS 2 Transfer 发布控制速度。

## 风险与硬编码

1. **控制端固定**：Transfer 与 RTSP 均绑定 `192.168.1.120`；换控制器/网络必须配置化。
2. **日志路径固定**：`Jetson2App.cpp` 固定写 `/home/ysc/lite_cog_ros2/transfer/nx2app_log.txt`，目录权限或迁移失败会影响日志。
3. **安全链路依赖完整**：缺失超声、点云、里程计或 TF 时，VOA 的安全判断不能认为可信；应通过 `sensor_checker` 状态联合判定。
4. **Track 非服务化**：没有可用的 Track 启动脚本；`track.service` 仍指向 ROS 1 下不存在的脚本，不能代表 ROS 2 Track 的自动启动能力。
5. **模型/GPU 依赖**：YOLO engine、NVIDIA 解码器与 GStreamer 管线均依赖具体 GPU/驱动环境。
