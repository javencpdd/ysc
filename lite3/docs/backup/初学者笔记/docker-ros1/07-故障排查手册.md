# 故障排查手册

## 总原则

按依赖层级从下到上排查：

```text
Docker
  → 容器与宿主网络
  → X11
  → OpenGL
  → ROS 环境与 Master
  → 节点和话题
  → RViz / Gazebo 专属问题
```

不要看到 RViz 起不来就随机修改 `ROS_IP`，也不要看到串口权限错误就直接给容器 `--privileged`。

## 快速检查表

| 层级 | 命令 | 正常结果 |
|---|---|---|
| Windows | `wsl -l -v` | 发行版为 VERSION 2 |
| Docker | `docker version` | Client/Server 都正常 |
| Docker | `docker run --rm hello-world` | 容器成功运行 |
| 容器 | `cat /etc/os-release` | 与预期镜像一致 |
| DNS | `getent hosts host.docker.internal` | 能解析宿主地址 |
| X11 | `echo $DISPLAY` | `host.docker.internal:0.0` |
| X11 | `xeyes` | Windows 出现窗口 |
| OpenGL | `glxinfo -B` | 显示 renderer/version |
| ROS 环境 | `rosversion -d` | `noetic` |
| Master | `rosnode list` | 至少能看到 `/rosout` |
| Topic | `rostopic echo <topic>` | 持续收到消息 |
| TF | `rosrun tf tf_echo A B` | 持续输出变换 |
| 时间 | `date +%s` | 与宿主时间基本一致 |
| 仿真时间 | `rostopic echo /clock` | 启用仿真时间时持续更新 |

## `cannot open display`

容器中检查：

```bash
echo "$DISPLAY"
getent hosts host.docker.internal
nc -vz host.docker.internal 6000
xeyes
```

处理顺序：

1. 确认 VcXsrv 正在运行且 display number 为 0；
2. 确认 `DISPLAY=host.docker.internal:0.0`；
3. 检查 Windows 防火墙是否允许可信网络访问；
4. 暂停 VPN 后做一次隔离测试；
5. 仅在可信网络的排错阶段临时测试 `Disable access control`。

## Qt / MIT-SHM 错误

```bash
export QT_X11_NO_MITSHM=1
```

重新启动 Qt 程序。该变量用于解决跨主机 X11 下共享内存不可用的问题。

## RViz 崩溃或黑屏

```bash
env | grep -E 'DISPLAY|QT|LIBGL|ROS'
glxinfo -B
LIBGL_ALWAYS_SOFTWARE=1 rviz
```

若软件渲染能运行，说明问题更可能位于 GLX/硬件渲染路径。随后应优化显示方案或迁移到 WSLg/原生 Linux，而不是长期依赖软件渲染。

## Gazebo GUI 卡顿或崩溃

```bash
gzserver --verbose
roslaunch gazebo_ros empty_world.launch gui:=false
rostopic list
gzclient --verbose
```

先确定 `gzserver` 是否工作，再判断 `gzclient`。容器外同时查看：

```powershell
docker stats ros1-noetic
```

## Master 可见但 topic 不通

```bash
echo "$ROS_MASTER_URI"
echo "$ROS_IP"
echo "$ROS_HOSTNAME"
rosnode list
rosnode info <node>
rosnode ping <node>
rostopic info <topic>
rostopic echo <topic>
```

重点查看 `rosnode info` 中节点声明的 URI 是否能从订阅端访问。多容器场景使用 Compose 服务名；局域网多机场景使用可路由 LAN 地址。

## 时间与 TF 错误

Windows PowerShell：

```powershell
[DateTimeOffset]::UtcNow.ToUnixTimeSeconds()
```

容器：

```bash
date +%s
rosparam get /use_sim_time
rostopic echo /clock
```

睡眠/唤醒后若 WSL 时钟明显异常，可执行：

```powershell
wsl --shutdown
```

随后重新启动 Docker Desktop。注意区分系统时间和 ROS 仿真时间。

## 通用诊断脚本

```bash
#!/usr/bin/env bash

echo '===== OS ====='
head /etc/os-release

echo '===== DISPLAY ====='
echo "DISPLAY=${DISPLAY:-<unset>}"
getent hosts host.docker.internal || true

echo '===== NETWORK ====='
ip -brief addr
ip route

echo '===== OPENGL ====='
glxinfo -B 2>/dev/null || echo 'glxinfo failed'

echo '===== ROS ====='
echo "ROS_DISTRO=${ROS_DISTRO:-<unset>}"
echo "ROS_MASTER_URI=${ROS_MASTER_URI:-<unset>}"
echo "ROS_IP=${ROS_IP:-<unset>}"
echo "ROS_HOSTNAME=${ROS_HOSTNAME:-<unset>}"
rosnode list 2>&1 || true

echo '===== TIME ====='
date -Ins
date +%s
```

保存为 `~/check_ros_env.sh` 后运行：

```bash
chmod +x ~/check_ros_env.sh
~/check_ros_env.sh
```
