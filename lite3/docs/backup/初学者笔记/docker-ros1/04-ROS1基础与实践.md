# ROS 1 基础与实践

## 先理解 ROS Graph

ROS 1 的基本对象包括：

| 对象 | 作用 |
|---|---|
| Node | 独立运行的功能进程 |
| Topic / Message | 异步、多对多数据流 |
| Service | 同步请求与响应 |
| Parameter | 由 Parameter Server 管理的配置 |
| Master | 帮助节点注册和发现彼此 |
| Launch | 统一启动节点、参数和命名空间 |

Master 负责发现，不负责转发全部业务数据。节点完成注册后通常直接连接，这也是 ROS 1 多机网络不能只考虑 11311 端口的原因。

## 用 turtlesim 完成闭环练习

终端 1：

```bash
roscore
```

终端 2：

```bash
rosrun turtlesim turtlesim_node
```

终端 3：

```bash
rosrun turtlesim turtle_teleop_key
```

依次检查：

```bash
rosnode list
rosnode info /turtlesim

rostopic list
rostopic info /turtle1/cmd_vel
rostopic info /turtle1/pose
rostopic echo /turtle1/pose
rostopic hz /turtle1/pose

rqt_graph
```

手工发布速度：

```bash
rostopic pub -r 10 /turtle1/cmd_vel geometry_msgs/Twist \
  "{linear: {x: 1.0}, angular: {z: 0.5}}"
```

应能解释下面的数据流：

```text
turtle_teleop_key
  → /turtle1/cmd_vel
  → turtlesim_node
  → /turtle1/pose
  → rostopic echo 或自定义控制节点
```

## 编程练习顺序

建议逐项独立完成：

1. Python publisher 和 subscriber；
2. C++ publisher 和 subscriber；
3. service server/client；
4. 参数读取、动态配置和命名空间；
5. launch 文件；
6. 订阅 `/turtle1/pose` 并闭环控制 `/turtle1/cmd_vel`。

完成标准不是“复制代码能运行”，而是拿到一个消息定义后，能独立编写节点，并知道如何使用 `rosnode`、`rostopic` 和日志定位错误。

## TF、URDF 与 RViz

推荐顺序：

```text
TF 坐标变换
  ↓
URDF 的 link 与 joint
  ↓
robot_state_publisher
  ↓
RViz 的 Fixed Frame 与 RobotModel
```

典型坐标树：

```text
map
└── odom
    └── base_link
        ├── laser_link
        ├── camera_link
        └── imu_link
```

URDF 至少需要理解：`link`、`joint`、`visual`、`collision` 和 `inertial`。在 RViz 中依次练习 Grid、TF、RobotModel、LaserScan、PointCloud2、Image、Path、Pose、Marker 和 Map。

## Gazebo、SLAM 与 Navigation

Gazebo 学习重点是区分：

```text
URDF/SDF → gzserver（物理、传感器、插件）
                    ├── ROS topics
                    └── gzclient（图形界面）
```

SLAM 与导航阶段要能解释：

```text
LaserScan + Odometry + TF
  → SLAM
  → OccupancyGrid
  → move_base / costmap
  → /cmd_vel
  → 底盘控制器
```

传统练习包可按镜像中的软件源实际可用情况安装：

```bash
apt-get update
apt-get install -y \
  ros-noetic-slam-gmapping \
  ros-noetic-navigation
```

验收时应能回答：

- `/scan` 和 `/odom` 分别由谁发布？
- `map → odom` 与 `odom → base_link` 分别由谁维护？
- 为什么导航需要 costmap？
- `/cmd_vel` 没有输出时，应检查规划器、TF、传感器还是底盘？
