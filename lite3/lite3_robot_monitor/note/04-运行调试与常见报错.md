> 已知限制、`backend/config.py`。

## 4.1 `connected` 一直 false（面板显示 Offline）

**现象**
页面能打开，但状态灯一直是 Offline，`/api/status` 里 `connected=false`。

**原因分析**
数据链路任意一段断了都会是这个结果，盲目重启服务没用 —— 必须**先分段定位**。

**解决方案（按这个顺序，不要跳步）**

```bash
# 第 1 步（最有价值）：103 到底有没有收到状态？
sudo tcpdump -i any -nn udp dst port 43897 -c 5
```

- **有输出** → 数据到了 103，问题在 Monitor：检查 `LITE3_UDP_IFACE` 是否抓错网卡、
  是否有 `CAP_NET_RAW`（见 3.2 / 3.3）。
- **无输出** → 数据没到 103，去查 120 侧 `jy_exe/conf/network.toml`
  （`local_port` / `target_port` 配置），这已经不是 Monitor 的问题。

```bash
# 第 2 步：看服务日志
journalctl -u lite3-monitor -n 50
# 第 3 步：确认生效模式
curl -s http://127.0.0.1:8000/api/status | python3 -m json.tool
```

**规避建议**
把 `tcpdump` 那一条当作**唯一的第一步**。它能一句话把问题切成"数据没来"和"我没抓到"，
比看十分钟日志有效。

## 4.2 `udp_mode` 变成 `bind`（静默降级）

**现象**
`/api/status` 的 `udp_mode` 是 `bind` 而不是期望的 `sniff`。

**原因分析**
`LITE3_UDP_MODE=auto` 时优先 sniff，**失败会自动退回 bind**。
在 103 上退回 bind 意味着要占用 43897 —— 会触发 3.1 那个大坑。

**解决方案**
查日志找降级原因（绝大多数是权限）：

```bash
journalctl -u lite3-monitor -n 50 | grep -i "permission\|sniff\|fallback"
```

确认 unit 里有 `AmbientCapabilities=CAP_NET_RAW`（见 3.2），然后显式固定：

```ini
Environment=LITE3_UDP_MODE=sniff
```

**规避建议**
103 上**不要依赖 auto**，显式写 `sniff`，这样一旦失败会直接报错而不是悄悄抢端口。

## 4.3 浏览器打不开 `http://192.168.1.103:8000`

**现象**
服务 `active`，但笔记本浏览器访问超时。

**原因分析**
两种可能：服务没真正监听，或防火墙拦了 8000 端口。

**解决方案**

```bash
systemctl status lite3-monitor          # 确认 active
sudo ss -tlnp | grep 8000               # 确认在监听
sudo ufw allow 8000/tcp                 # 放行端口
```

**规避建议**
服务是 `LITE3_HTTP_HOST=0.0.0.0`（默认），对外只占用 **8000 一个端口**，放行这一条即可。

## 4.4 改了配置没生效

**现象**
改了 unit 的 `Environment=` 或环境变量，行为不变。

**原因分析**
`backend/config.py` 的配置是 **frozen dataclass**，在 **import 时**读取并固化，运行期不重读。

**解决方案**

```bash
sudo systemctl daemon-reload     # 改了 unit 文件才需要
sudo systemctl restart lite3-monitor
```

**规避建议**
用 `/api/status` 或 `/api/ros` 的字段**反查**是否真的生效，别凭感觉判断。

## 4.5 控制通道：能下发但风险极高

**现象**
需要让机器人动起来，前端却无法下发速度指令。

**原因分析**
控制通道**默认整个关闭**：`LITE3_CTRL_ENABLED=false`。这是刻意为之的安全设计。

**解决方案**（仅在理解风险后开启）

```ini
Environment=LITE3_CTRL_IP=192.168.1.120
Environment=LITE3_CTRL_PORT=43893
Environment=LITE3_CTRL_HEARTBEAT=0.25
Environment=LITE3_CTRL_LEASE=5.0
Environment=LITE3_CTRL_MAX_LINEAR=1.0
Environment=LITE3_CTRL_MAX_ANGULAR=1.5
Environment=LITE3_CTRL_ENABLED=false    # 保持 false，由前端按需启用
```

> ⚠️ **风险提示**：控制指令直连 120 上的闭源 `jy_exe`（`192.168.1.120:43893`），
> **不经过 103 的 VOA 安全层**——限速、避障、防撞**均不生效**。
> 务必在开阔场地、机器人架空或有人持遥控器待命时使用。

关键约束：
- **心跳周期必须 < 1s**（官方 SDK：1s 无指令即收回控制权），默认 0.25s。
- **租约 5s**：浏览器关闭后自动停心跳并下发零速，防"后台持续发送"。
- 速度硬限幅在后端二次夹取：前后 ±1.0、左右 ±0.5、旋转 ±1.5（不信任前端）。

**规避建议**
保持 `LITE3_CTRL_ENABLED=false`，让"启用"成为一个**显式的人为动作**，
避免服务重启后自动进入可控制状态。

## 4.6 下发速度后机器人方向不对

**现象**
下发正值"向右"，机器人却向左。

**原因分析**
固件实际方向与协议文档定义不一致（或对"右"的参考系理解不同）。这是**实机差异**，不是 bug。

**解决方案**
用三个逐轴取反开关纠正，不需要改代码：

```ini
Environment=LITE3_CTRL_INVERT_VEL_X=false
Environment=LITE3_CTRL_INVERT_VEL_Y=true     # 实机实测左右相反，默认已开启
Environment=LITE3_CTRL_INVERT_VEL_YAW=false
```

**规避建议**
⚠️ **文档可能滞后于代码**：`README.md` 配置项表把 `LITE3_CTRL_INVERT_VEL_Y` 的默认值写成
`false`，但 `backend/config.py` 里实际是 **`True`**（代码注释写明是 103 实机实测后改的）。
**以 `backend/config.py` 为准**，发现文档与代码冲突时先读代码。

## 4.7 已知限制：机体系速度恒为 0

**现象**
走 ROS 数据源时，`velocity_body`（机体系速度）始终是 0。

**原因分析**
`docs/ros_troubleshooting.md` 明确记录：
`ros_bridge_node.py` 只在初始化时把它设为 0，**没有任何话题回调会更新它**。

**解决方案**
暂时以**世界系速度**为准，不要依赖机体系速度做判断。

**规避建议**
这是已知限制而非故障，别浪费时间去 debug 它；如果后续需要，得在桥接节点里补上对应订阅。

## 4.8 心跳记录把业务指令历史挤掉了

**现象**
控制审计里看不到较早的业务指令。

**原因分析**
心跳以 4Hz 发送，审计是 200 条环形缓冲；高频心跳会把业务指令挤出历史。

**解决方案**
项目已做裁剪：心跳记录只保留最近 20 条（见 `control_service.AUDIT_HEARTBEAT_KEEP`），
保证业务指令不被挤掉。

**规避建议**
排查控制问题时，注意审计里看到的是**裁剪后**的结果，不代表完整下发序列。

## 4.9 前端跨域直连后端

**现象**
前后端分离部署（前端不在 103 上）时接口请求失败。

**原因分析**
默认前端由后端静态托管（`LITE3_SERVE_FRONTEND=true`）；分离部署时需要指定后端地址。

**解决方案**
前端用 `VITE_BACKEND_URL` 指定后端地址。

**规避建议**
【待验证】跨域模式下的 CORS 具体行为未在本项目中完整实测，
若遇到问题优先改回同源托管（把 `dist` 放到 103 上由后端托管）。

## 4.10 服务单进程资源占用（容量参考）

| 指标 | 参考值 |
| --- | --- |
| 常驻内存 | 约 40–60 MB |
| 空闲 CPU | < 1% |
| 对外端口 | 仅 8000（HTTP/WebSocket） |

**规避建议**
资源开销很小，与现有 ROS 服务共存没有压力；真正要注意的是**别用 bind 抢端口**（3.1）
和**别抓无关网卡流量**（3.3）。
