# Lite3 Robot Monitor 踩坑笔记

面向**第一次接触本项目、需要在 103 上把监控跑起来**的人。

这里记录的都是项目开发/部署过程中**真实发生过**的问题，依据来自：
`README.md`、`deploy/install.sh`（含脚本注释里的历史坑）、`deploy/README.md`、
`docs/ros_bridge.md`、`docs/ros_troubleshooting.md`、`backend/requirements.txt`
以及 systemd unit 模板。凡是代码和脚本里无法推断的内容，均已标注 **【待验证】**，请勿当作既定事实。

## 一句话讲清这个项目在干什么

103（Jetson 感知导航主机）上跑一个 FastAPI 服务，**旁路**读取机器人运动主机 120
发来的 UDP 遥测报文（目的端口 43897），解析后通过 WebSocket 推给浏览器面板；
另外可选地向 120:43893 下发控制指令（默认关闭）。

关键约束：**只读为主**，不能干扰 103 上已有的 `transfer_ros2` / ROS / Nav2。

## 推荐阅读顺序

1. **想快速跑通**：`01` → `02`（只看到"打包上传"）→ `05`（看到"验证"）→ 打开 `http://192.168.1.103:8000`
2. **面板能开但显示 Offline**：直接跳 `03`，先看"第 1 条：43897 端口冲突"，再按 `04` 的排查顺序走
3. **要切 ROS1 / ROS2 环境**：看 `06`（双栈现状、端口归属、切换命令、重启被抢回端口的坑、
   双栈并存导致检测结果不一致）；监控侧"自动识别版本"的机制在 [README 第十三章](../README.md)
4. **要改代码**：`02` 的"增量更新"整节（**不要用 `install.sh` 做日常更新**）
5. **要开控制通道**：`04` 的控制通道小节 —— 它绕过 VOA 安全层，务必先读风险

## 贯穿全篇的三条铁律

1. **绝不 bind 43897**。103 上这个端口已被 `transfer_ros2` 占用，抢走会导致
   `leg_odom2` / `/imu/data` 断流、Nav2 丢失本体里程计。监听一律走 `sniff`（AF_PACKET 旁路）。
2. **改配置必须重启服务**。`backend/config.py` 的配置是 **frozen dataclass**，在 import 时固化，
   改环境变量不重启不会生效。
3. **新增后端代码保持 Python 3.8 兼容**。103 是 Ubuntu 20.04 / Python 3.8，
   不要用 3.9+ 的内置泛型写法（`list[str]`）和 3.10+ 的 `X | None` 语法，否则启动直接失败。

## 常用一条命令定位法

数据链路出问题时，**先分清是"数据没到 103"还是"Monitor 没抓到"**：

```bash
sudo tcpdump -i any -nn udp dst port 43897 -c 5
```

- 有输出 → 数据在，问题在 Monitor（查网卡名、CAP_NET_RAW 权限）
- 无输出 → 数据没到 103，去查 120 侧 `jy_exe/conf/network.toml`

这条命令是全套排查里性价比最高的一步，后面的文档会反复引用它。
