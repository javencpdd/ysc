# NOS/GOS 出公网固化方案（103 主机拒绝其他内外主机连接外部网络）

> 适用对象：M20 Pro 三主机中 **NOS(10.21.31.106)** 与 **GOS(10.21.31.104)**。
> 结论先行：**NOS 默认网关写死成不可达的内网总关 `10.21.31.99`、DNS 配了不可达的 `8.8.8.8`，所以无公网、域名解析失败；GOS 默认网关早已指向 AOS，本就正常。**
> 修法：把默认网关改指 **AOS(10.21.31.103)** + DNS 设 **腾达 `192.168.0.1`**，并固化到 netplan，重启仍生效。

---

## 1. 现象

在 NOS 上执行：

```
user@nos:~$ ping -c 3 bilibili.com
ping: bilibili.com: Temporary failure in name resolution
```

- `ping 8.8.8.8`（纯 IP、不走 DNS）同样 100% 丢包 → 不是 DNS 单点问题，是**根本没有出网路径**。
- 但 `ping 192.168.0.x`（PC 段）能通 → 因为 14 号专门加过一条更具体的 `192.168.0.0/24 via 10.21.31.103`，它只覆盖 PC 段，不覆盖公网。

## 2. 根因（只读核查实证）

### 2.1 NOS 默认网关是死的
```
default via 10.21.31.99 dev eth1 proto static metric 20101
```
实测 `ping 10.21.31.99` = **100% 丢包**，所以 NOS 对一切非本子网目标都没有出口。

### 2.2 NOS 的 DNS 也不可用
`/etc/resolv.conf` 是 systemd-resolved 的 stub（`nameserver 127.0.0.53`），其上游 DNS 本应由网关 `.99` 下发——但 `.99` 死了，resolver 没有任何能问的服务器，于是直接报 `Temporary failure in name resolution`。
出厂 netplan 把 DNS 写成了 `8.8.8.8`，而 `8.8.8.8` 经死网关不可达（且腾达上游也不放行 8.8.8.8）。

### 2.3 GOS 其实是好的（无需改）
GOS 的 `/etc/netplan/config.yaml` 已经是：
```
ethernets.eth0:
  addresses: [10.21.31.104/24]
  gateway4: 10.21.31.103      # 早已指向 AOS
  nameservers.addresses: [192.168.0.1]
```
所以 GOS 本就能上公网。脚本在 GOS 上**幂等跳过**，不会造成任何改动。

## 3. 为什么改指 AOS 就能上公网（架构原理）

三主机里**只有 AOS 有公网出口**：AOS 的 `p2p0`（192.168.0.196）连腾达路由器，实测 `ping bilibili.com` 0% 丢包，DNS 用的是腾达 `192.168.0.1`。

并且 AOS 上**已经存在**我们 14 号配置好的 NAT 与转发规则（无需再动 AOS）：

```
iptables -t nat -A POSTROUTING -s 10.21.31.0/24 -o p2p0 -j MASQUERADE
iptables -S FORWARD   # 含 -i p2p0 -o eth2 -j ACCEPT 与 -i eth2 -o p2p0 ... ACCEPT
```

因此：**只要让 NOS/GOS 的默认网关指向 AOS(10.21.31.103)**，它们的出网流量就会被 AOS 做源地址转换（MASQUERADE）后从 `p2p0` 出去，回包再经 AOS 转发回来 —— 借 AOS 的 NAT 上公网。

> 注：改动只影响"公网/未知目标"的出口。NOS/GOS 到同子网（如 `10.21.31.0/24`、`10.21.33.0/24`、`10.21.34.0/24`）都是内核直连路由，**不经过网关**，机器人内部通信不受影响。

## 4. 固化脚本

脚本源码（可入库留底）：`m20Pro/scripts/enable-internet-via-aos.sh`
已部署到两台主机：`/home/djw/tools/enable-internet-via-aos.sh`（已 `chmod +x`）

脚本特性：
- **自动探测**默认路由接口（NOS=eth1，GOS=eth0），不写死设备名；
- **幂等**：网关已是 AOS 时跳过，不改任何东西；
- **真正持久化**：走 `netplan set` 改写 `/etc/netplan/config.yaml` 再 `netplan apply`，重启不丢（单纯改运行路由会被 netplan 覆盖，故必须改 yaml）；
- **自带回滚**：改动前自动备份 `config.yaml` 到 `config.yaml.bak-<时间戳>`，可用 `--rollback` 还原；
- 需要写 netplan 时自动 `sudo` 提权（交互式提示输入 sudo 口令，口令不落盘）。

### 用法
```bash
# 预览将要做的改动（只读，不改任何东西）
/home/djw/tools/enable-internet-via-aos.sh --check

# 真正执行：备份 netplan → 改网关/DNS → netplan apply → 验证
sudo /home/djw/tools/enable-internet-via-aos.sh

# 万一改坏，回退到最近一次备份并重新 apply
sudo /home/djw/tools/enable-internet-via-aos.sh --rollback
```

### 在 NOS 上的效果（--check 预览）
```
默认路由接口 : eth1
当前默认网关 : 10.21.31.99
目标网关     : 10.21.31.103 (AOS)
目标 DNS     : 192.168.0.1
[check] 将改 netplan: ethernets.eth1.gateway4=10.21.31.103 ; nameservers.addresses=[192.168.0.1]
```

### 在 GOS 上的效果（--check 预览，幂等）
```
默认路由接口 : eth0
当前默认网关 : 10.21.31.103   # 已是 AOS
[check] 默认网关已是 10.21.31.103, 无需改动(幂等).
```

## 5. 执行后验证（在对应主机上）

```bash
# 默认路由应指向 AOS
ip route show default
#   NOS: default via 10.21.31.103 dev eth1
#   GOS: default via 10.21.31.103 dev eth0

# DNS 应为腾达
resolvectl dns eth1      # NOS
resolvectl dns eth0      # GOS

# 解析 + 连通
ping -c3 bilibili.com    # 应 0% 丢包
```

## 6. 回滚（如需）

```bash
sudo /home/djw/tools/enable-internet-via-aos.sh --rollback
# 还原 /etc/netplan/config.yaml 的最近一次时间戳备份并 netplan apply
```

也可手动：`cp /etc/netplan/config.yaml.bak-<时间戳> /etc/netplan/config.yaml && netplan apply`

## 7. 注意事项

- **AOS 不能动**：本方案完全不修改 AOS；AOS 的 masquerade/FORWARD 规则是 14 号已配好的，NOS/GOS 借它出网。
- **netplan 是真相源**：这些主机用 `renderer: NetworkManager`，netplan 在开机/apply 时重新生成 NM 连接，所以只改运行路由或 `nmcli modify` 都会被覆盖。**必须改 `/etc/netplan/config.yaml`** 才能持久，脚本正是这么做的。
- **`netplan apply` 不会掉 SSH**：脚本只改网关与 DNS，不动物理地址（如 `10.21.31.106/24` 保持不变），故接口不会 down，SSH 不会断。
- **sudo 口令**：这些主机 `user` 的 sudo 口令为单引号 `'`，脚本提权时会交互式提示输入。
