# 控制安全闸与控制权归属

> 2026-10-19 建立。回答两个问题：
> ① **"开启控制 / 停用控制"到底是什么**（`ControlGateway` 的分层闸）；
> ② **多个终端同时打开控制台会怎样**（控制权归属 / 多操作员互斥）。
>
> 代码：`backend/control/control_gateway.py`、`backend/control/axis_watchdog.py`、
> `backend/errors.py`、`backend/main.py`；前端 `useRobotState.js` + `MotionPanel.vue`。

---

## 1. "开启控制 / 停用控制"是什么

它是**后端一把本地总闸**（`ControlGateway`），切换的是"这台控制台能否往机器人
AOS `basic_server`（UDP :30000）发**驱动类**指令"。**不向机器人发任何"开启"帧**，
也不动硬件。

| 级别 | 状态 | 能发什么 |
|---|---|---|
| **L0（只监）** | 停用（默认） | 仅 `always_allowed` 安全指令：`heartbeat` / `soft_estop` / `clear_estop` / `sleep_query` |
| **L1（可控）** | 开启 | 其余指令（轴运动、设备供电、休眠…）在其它闸满足时可发 |

### 开启做了什么
`POST /api/v1/control/acquire`（旧 `/enable` 仍兼容）：
1. 要求 `confirmed=true`（前端二次确认），否则 `CONFIRM_REQUIRED`；
2. 登记 owner（见 §2），`_enabled=True`；
3. 开租约（默认 5s，前端每 2s 续约）。

### 停用做了什么（`release` / `disable`）
**先保命再关门**：
1. **先补发一帧安全零位**（全轴速度 0，`send_safety_zero`，豁免所有闸）；
2. `_enabled=False`、租约清零、释放归属；
3. 回到 L0。

> 与**软急停**完全不同：`soft_estop` 是**真正发给机器人**的指令（车进入急停态、
> 锁存 `_estop`）；而"开启/停用控制"是纯本地许可，机器人毫不知情。
> 急停 `always_allowed`——即使停在 L0 也能按。

### 一条指令要过的闸（按序）

```
blacklist → enabled → owner → estop → telemetry → lease → precondition
         → device_switch → confirm → 编码 → 发 UDP 帧
```

| 闸 | 拦什么 |
|---|---|
| blacklist | `Charge=2`（清除充电状态）永远拒绝 |
| **enabled** | 总开关 L0/L1（本文件 §1 主角） |
| **owner** | 控制权归属（§2，2026-10-19 加） |
| estop | 急停锁存期间除解急停外全拦 |
| telemetry | "蒙眼不开车"：心跳停了禁止驱动 |
| lease | 租约过期（5s 未续约）禁止驱动 |
| precondition | 轴指令需 `MotionState∈{1,17}` 且常规模式 |
| device_switch | 设备断电不可逆：关闭需二次确认；运动中禁关雷达 |
| confirm | 整车行为（休眠 / 关回零）危险方向需确认 |

## 2. 控制权归属（多操作员互斥）

### 为什么必须做

控制闸是**全局单例**——`_svc()` 只有一个 `ControlGateway`，所有浏览器共享同一个
`_enabled`。改造前是"**谁最后点谁说了算**"，两类真实风险：

1. A 正在遥控，B 点"停止"就把 A 掐断（A 表现为"点了没反应"）；
2. A、B 可**同时开启、同时往一条狗发运动指令**（两人开一台车）。

### 机制

同一时刻**只有一个 owner**，按终端 `session_id` 认定：

- **无主模式**（`_owner is None`）：单测 / 本机脚本直接 `enable()` 的情形，
  **任何人可操作**（向后兼容，旧行为不变）；
- **有主模式**：非 owner 发驱动类指令一律 `NOT_OWNER` / **409**；
  安全指令（心跳 / 软急停）**豁免**——被别人占着也必须能急停。

owner 超时（默认 **15s** 未续约）自动释放，**释放前先发零位**。
这一条是防"浏览器崩溃 / 拔网线 → 控制权被僵尸终端永久占死"。

### API

| 端点 | 作用 |
|---|---|
| `POST /api/v1/control/acquire` | 申请/接管控制权（body: `session_id`,`label`,`force`,`confirmed`） |
| `POST /api/v1/control/release` | 释放（`session_id`；非 owner 被拒，除非 `force`） |
| `POST /api/v1/control/enable` | **兼容旧入口**，按 `enable` 分派到 acquire/release |
| `POST /api/v1/control/lease` | 续约；带 `session_id` 时**非 owner 续约无效**（返回 0） |

返回码：`CONTROL_HELD`（他人占用）+ `owner` 信息 / `NOT_OWNER` / `NO_SESSION`。

### 前端

- `useRobotState.js` 用 **sessionStorage** 生成 `session_id`（同标签页刷新不变，
  新标签页 = 新终端），所有控制请求带上；
- `MotionPanel.vue`：非 owner 时驱动按钮置灰、标题显示"控制权在「xxx」手中，
  本终端只读"，并提供「接管控制权」（`force=true`，二次确认）。

> ⚠️ **ADR-020/021 铁律**：`isControlOwner` 必须在 App.vue **解构到顶层**再用。
> composable 返回普通对象，不解构拿到的是 Ref、恒为真 —— 会让"非 owner 置灰"
> 彻底失效。

### 看门狗（持续驱动）不能绕过

摇杆 / 定时移动走 `AxisWatchdog`，它循环里调 `gateway.execute()`。
**必须透传 `session_id`**，否则：
- owner 自己的持续开车会被归属闸当成"没带身份"**拒掉**（真实回归）；
- 非 owner 则可能从侧门绕过互斥。

现在 `feed()` / `feed_timed()` 直接校验归属，非 owner **拒绝启动**（返回 False，
快速失败，强于"启动了再每帧被拒"）。

安全豁免 / 接管先停车 / 超时不锁死 / 向后兼容 / 看门狗）。

| 步骤 | 结果 |
|---|---|
| A 申请 | ok，owner=A |
| B 申请 | `CONTROL_HELD` + 占用者信息 |
| B 下发指令 | `NOT_OWNER` / 409 |
| A 下发指令 | ok |

| B 释放 | 回到 L0，`held=False` |

## 4. 踩坑

### ★ Python 3.8 不支持 `X | None`（真机实测把服务搞挂了）

真机 AOS 是 **Python 3.8.10**。我在 `control_lease` 写了
`req: LeaseRequest | None = None` → 服务**启动直接崩**（FastAPI 解析注解时
`TypeError: Unable to evaluate type annotation 'LeaseRequest | None'`），
systemd 反复重启，HTTP 全无响应。

**本机（3.13）pytest 全绿也测不出来**——这是纯运行时注解求值，只有真机 3.8 会炸。

修法：一律 `Optional[X]`（`backend/config.py` 开头注释本就写了
"3.9+ 内置泛型统一走 `typing`"，别违反）。

> **教训：改后端后必须在真机上确认 `curl /health` 有响应，不能只信本机单测。**

### 无主模式必须视为"可操作"

`isControlOwner` 在 `held=False` 时返回 **True**（不是 False）。
否则单机 / 老后端场景下"控制权未占用"会被当成"我不是 owner"，
所有驱动按钮误置灰——这是会直接影响使用的回归。

### ★"只有我一个人，为什么说控制权被占用？"（独立端点漏传身份）

**2026-10-19 真踩（用户截图）**：单人使用，机器人设置面板报
`NOT_OWNER 控制权已被终端 term-od6 占用，当前请求未携带终端标识`。

原因有两层：
1. **"占用者"就是他自己**——`term-od6` 是他的终端短码。他点过开启控制，
   owner 登记成了自己的 session；
2. 但**机器人设置面板走的是 `/api/v1/robot/light|auto_reset|sleep` 独立端点**，
   不是 `/control/command`。第一版只给 `useRobotState.js` 里的
   `sendCommand/sendAxis` 加了 `session_id`，**覆盖不到这些独立端点** →
   请求不带身份 → 归属闸判成"陌生终端"。

**根本修法（防止再漏）**：标识改由 **`api/index.js` 的 `postJson` 统一注入**
（`getSessionId()` 与 composable 共用同一个 sessionStorage key），
任何面板、任何新端点都不需要自己记得带。同时后端 4 个 robot 端点补
`session_id` 入参并透传。

**文案也要能指导操作**：原来只说"被占用"，单人会以为是别人。
现在改成 `本终端尚未登记控制权（当前由终端 xxx 持有）。如果你就是操作者，
请到「运动控制」点「接管控制权」`。

> 顺带：`auto_reset_query` / `sleep_query` 是只读查询且已标 `always_allowed`，
> **归属闸豁免**——非 owner 也能读配置（不然只读面板都会空白）。

### 接管/超时释放前必须先发零位

换人（force 接管）或操控者失联（超时）时，车可能正在运动。
两者都在**改归属前**发一帧安全零位，不能"换人时车还在走"。
