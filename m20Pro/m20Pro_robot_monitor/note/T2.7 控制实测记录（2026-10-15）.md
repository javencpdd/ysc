关键设计（踩坑后定型）：

- **禁用** `continuous=true` 与 `axis/stop`（当时实现都会触发 `AxisWatchdog._trip()` = 零位 + 软急停 → 车趴下）→ 改用 **20Hz 循环单发 `POST /control/axis`（`continuous:false`）+ 1.5s 周期 lease 续约 + 轮末只发一次零位**，由 rl_deploy 侧 150ms `MonitorSteer` 看门狗自然清零 → 车平滑停下、保持站立（`ms=17` 不变）。
- 前置检查：`motion_state ∈ (1,17)`、`mode==0`、非充电；支持 `--dry` 预演。
- CSV 输出（196 `/tmp/axis_visible_%H%M%S.csv`）：`phase,rel_t,pos_x,pos_y,pos_z,vx,vy,wz,h,loc,ms,gait,mode,ok,reason`。

## 3. 实测数据

### 第一轮：0.4 / 0.7 / 1.0（各 2.5~3s @20Hz）

| 控制值 x | `/MOTION_INFO.vel_x` | 用户现场反馈 |
|---|---|---|
| 0（静止底噪） | ≈0.066 | — |
| 0.4 | **0.548** 稳定 | "速度还可以"（≈0.5 m/s，正好对齐"最多 0.5"要求） |
| 0.7 | **1.113** | "太快了" |
| 1.0 | 正负跳变 | 用户抬车制止（腿空转打滑，非系统故障） |

控制台 audit：ok=160 / rej=0（对比此前 `rejected` 因租约问题的拒发，归零）。

### 第二轮：0.15 / 0.25 / 0.35（各 2s @20Hz）

| 控制值 x | vel_x 稳定读数 | 说明 |
|---|---|---|
| 0.15 | 0.204 | 可动，但偏"肉" |
| **0.25** | **0.316** | **用户选定：最舒服（默认档）** |
| 0.35 | 0.450 | 明显偏快 |
| — | — | 全程零波动，H 稳定 0.563~0.571，ok=120 / rej=0，停止时速度干净回落 |

### 标定结论

- **线性关系：`vel_x ≈ 1.34 × 控制值`**（近似过原点），可作限速映射依据。
- 安全阈值：**默认 0.25（≈0.32 m/s）｜上限 0.40（≈0.54 m/s）｜≥0.70 禁用**。
- 已固化：服务端轴值域钳制 `±0.40`（`config.py` / `control_gateway.py` / `config.example.toml`）；前端"速度上限"输入框（0.05~0.40，默认 0.25，localStorage 持久化；摇杆满舵 = 所填数值）。

## 4. 修正记录（首测暴露的两个真实缺陷 + 后续改造）

1. **"松手即软急停 → 车趴下"缺陷（已修）**：`AxisWatchdog.pause()` 原硬编码 `_trip()`（零位 + 软急停）。修复：新增 `trip` 参数与 `_soft_pause()`；`/control/axis/stop` 改传 `trip=False`（松手 = 零位停发，车侧 150ms 看门狗自然清零，不软急停）；**异常路径（WS 断开 / 页面隐藏 / feed 超时）仍默认 `trip=True`** 兜底。
2. **租约无自动续约缺陷（已修）**：前端 `useRobotState.js` 的 `renewLease()` 从未被调用，而 `lease_seconds=5s` → 开启控制 5 秒后所有指令被租约闸拒发（`rejected` 计数的隐藏增长源）。修复：前端每 2s 自动续约（仅 `control.enabled` 时）；196 实测 3 轮续约后 `lease_remaining` 恒 ≈5s。
3. **虚拟摇杆改造（深夜上线，参考 lite3 ControlPanel.vue）**：替换六宫格方向按钮。与 lite3 的关键差异 —— m20 看门狗要求 ≤250ms 持续 feed：拖动期间以 60ms（≈16Hz）定时器持续 `POST /control/axis {continuous:true}`（即使指针不动也必须续发）；**松手时先等在途最后一发落地再调 `axis/stop`**，避免残余 feed 在暂停后重新激活看门狗。
4. rl_deploy 日志交叉验证：测试时段（车时间 01:33~01:34）运控侧零错误零切换；01:35:15 `Recv [MotionState]: 4` = 用户测试后正常趴下（17→4）。`01:24:29 VelControl TOML 保存` = `autoResetJointsZero=true`（自动重置关节零位），**与速度无关**。

## 5. 新系统事实（影响后续设计）

- **`LocationStatus`（ASDU 1002/7 的 `pos_x/pos_y/pos_z`）不跟随短距离运动**：用户确认三轮测试"车是自由行走的"（累计约 2m），但 pos 坐标纹丝不动（`(-1.199, 0.546, 1.166)` 跨多次测试同值）。
  **结论：室内短距场景不能用 pos 坐标做位移校验 / 巡逻反馈**（待研究；可能因 LIO 未收敛或该坐标是重定位锚点）。

## 7. 事故复盘："一按前进就失控、摔倒或趴下"（2026-10-15 深夜）

**现象**：用户反馈按"前进"后车体失控、栽倒。车侧日志实锤复原了完整机制。

**取证**（basic_server / rl_deploy，车侧时间）：

- `01:49:18 Recv [MotionState]: 2` → `motion state: 17 -> 2`；4 秒后 `[SAFE_CTRL] 姿态异常: roll=-3.9 pitch=-20.3 yaw=-96.4`（**车体栽倒**）→ 车自动尝试"摔倒爬起"（`启动摔倒爬起`，步态 0xf003）→ `01:49:28.470` 又收到 `17 -> 2`（**再次软急停**，爬起被打断）→ `01:49:35 [VelControl] 摔倒爬起失败，触发软急停`。
- `01:51:36` 用户重新站立（`Recv [MotionState]: 1`）成功（步态 0x1001）；**17 秒后 `01:51:53.914 Recv [MotionState]: 2`** —— 用户按"前进"→ 车瞬间被软急停 → 趴下。
- 全天 `Recv [MotionState]` 历史呈 `1（站立）/ 2（软急停）` 交替（00:23–00:39 达 7 次以上）——即用户早前"反复站起和趴下"的实锤序列。
- **`Recv [MotionState]: 2` 就是我们 `soft_estop()` 的编码**（`patrol_codec`: `motion_state(2)` → `{"type":2,"command":22,"items":{"MotionParam":2}}`）→ **所有软急停均来自控制台**。另有一个 `10.21.33.11` 心跳客户端（仅订阅状态推送、从未发过指令）已排查排除。

**机制（旧版代码）**：

1. 前端 `press('前进')` 只发**一次** `continuous=true`（不持续 feed）→ 服务端看门狗 250ms 后 `feed_timeout` → `_trip()` = 零位 + **软急停**；
2. 松手 `axis/stop` → `pause()`（旧签名 trip=True）→ **又是软急停**；
3. ⇒ **无论按多久、怎么松，旧版每次"前进"操作都必然产生软急停**；车若在运动中 → 突然被打断 → 失稳栽倒（姿态异常 pitch −20.3° 实锤）。

**修复（2026-10-15 深夜，已部署并验证）**：

- **分级兜底**（`AxisWatchdog`）：
  - feed 停更 250ms → **零位一帧 + 停发**（不软急停），等待恢复；
  - 停更 / 断连持续 **10s**（`stale_estop_ms`）无恢复 → 升级零位 + 软急停（车已停稳，趴下无运动学风险）；
  - 异常断开（WS 断 / 页面隐藏）宽限期内**租约恢复即取消升级**（刷新页面不误伤）；
  - 用户松手（`trip=False`）→ 零位停发，无升级。
- **安全零位帧豁免四道闸**（`ControlGateway.send_safety_zero()`）：排查中发现次生缺陷——零位兜底此前会被租约闸拦截（审计 `axis -> rejected`），租约一过期兜底形同虚设。
- 前端摇杆加固：最多 3 发在途（网络慢时多发抗抖动）+ 8% 中心死区 + 首次使用警示文案。
- 验证：单测 **70 项全绿**；196 真机行为验证（车待机、全程不动车）：`feed → 停更 1.2s → stale=True 且 trip_count=0 → 恢复 feed → stale=False → 松手 → paused` 全链路符合设计。

## 8. 事故复盘（二）："突然又倒了" —— 延迟升级误伤 + y/yaw 死区观察（2026-10-15 凌晨 03:55 真实时间）

> ⚠️ §7 的"分级兜底（10s 升级软急停）"已被本节 v3 修订**取代**：自动软急停机制整体切除。
> 两次事故同源——**任何"自动软急停"都会把机器人放倒**。

**现象**：用户测试"左右平移 / 转向"时车体突然倒下，怀疑与 y/yaw 指令有关。

**取证**（控制台审计 500 条 + basic_server / rl_deploy 交叉验证；196 系统时间）：

- 用户完整操作序列（审计）：`02:12:20–47` 左右平移 y：0.02→0.06→0.12→0.20→0.30→±0.40（-0.40 保持 5s）；`02:12:49–55` 转向 yaw：±0.03→±0.40（+0.40 保持 3.5s）；`02:12:56–58` 前后 x：0→0.40 冲刺 + 反向 -0.40；`02:13:00.6` 短推（终点 yaw=0.20，x=-0.02）后 **02:13:01.47 客户端彻底静默 10 秒**——连 2s/次的租约续约都中断（页面冻结或链路断流；整场操作还有 3 次 0.5~1s 级瞬断，Q7 WiFi 抖动同源）。
- `02:13:11.500` 看门狗 `feed_stale_escalated` **自动软急停**（距静默起点 10.03s = `stale_estop_ms`）。
- 车侧：`02:13:11.501` `收到关节阻尼指令 → rl_control → joint_damping`（快照 300s）；**全天零姿态异常、零摔倒记录** → 车不是走摔的，是**站立中被卸力软塌**（用户视角 = "倒了"）。
- 结论：**与左右平移/旋转指令无关**——是"断流 10s 自动软急停"在无恢复场景下的误伤。estop 锁存后，用户后续所有操作被闸拦（`CONTROL_DISABLED`）。
- 车侧其余记录：`02:13:15.50 motion 2 -> 0`（软急停自动回 idle）；此后全天无任何 MotionState 指令。

**y/yaw "小值不动" 观察**：审计显示用户对平移/转向从小指令（0.02~0.06 级）逐级上探。判定为**车侧策略起动阈值**（RL 策略对平移/转向普遍存在最小速度阈值，前后方向阈值较低）+ y/yaw 未经实车标定——**非面板故障**；具体阈值待受控标定（方案：仿 x 的阶梯测试，从 0.10 起逐级上探，读 `linear_y` / `omega_z` 反馈）。

**修复（v3"只停不趴"——自动软急停整体切除，已部署验证）**：

- `AxisWatchdog`：删除 `stale_estop_ms` / 延迟升级链 / `_trip()` / `trip_count`；**任何中断（停更 / 松手 / 断连 / 停机）一律"零位一帧 + 停发等待恢复"**；软急停只能由人显式触发（面板按钮 / HTTP）。`pause()` 同时作废当前 feed——`resume()` 后必须等**新** feed 才发送（不会用旧轴值恢复驱动）。
- 依据：车侧 rl_deploy 自带 **150ms steer 看门狗**（无新数据即清零速度字段）——链路断了车**本来就会停**；控制台任何"自动放倒"只会制造事故（两次事故同源，车侧日志均为实锤）。
- 前端加固：`visibilitychange` 页面切后台**自动松手**（防"按住摇杆切走 → 浏览器节流定时器 → feed 断流"）；每次按下摇杆**先补一次续约**（防"从后台回来首推被租约闸拒"）；摇杆警示文案更新（平移/转向起动阈值说明）。
- 验证：单测 **69 项全绿**（含 10s / 60s / 10min 超长"不软急停"断言）；196 部署 + 真机行为验证通过；审计确认测试窗口内**零 soft_estop 下发**。

**给用户的操作提醒**：

- 本次"倒"非运动学事故；建议目视检查车体（关节/机身/外壳）后重新站立。
- y/yaw 未经实车标定：从小幅慢试做起；急停随时可用。断流/松手/切后台现在只会"停"，不会"趴"。
