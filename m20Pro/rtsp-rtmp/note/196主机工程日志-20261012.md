## 3. m20video 项目：双相机 RTSP→RTMP 推流

项目位置 `/home/user/rtmp_1012/`（196 主机），本地镜像 `../project/rtmp_1012/`。
目标：两路相机 RTSP → H.265→H.264 硬转码 → 推 `rtmp://172.31.68.227:1936/live/m20pro-f` 与 `m20pro-b`。
参考 120 主机（`~/rtsp_stream/`）的 `rtmp_forward.sh`。

交付物：`config.env` / `rtmp_forward.sh` / `run_all.sh` / start.sh / stop.sh / status.sh / `m20video` CLI（已装 `/usr/local/bin/m20video`）/ `install_service.sh` / `systemd/m20video.service`。
服务状态：已安装，**默认 `disabled` + `inactive`**（转码约占 2 个 CPU 核）。用 `sudo m20video up|down|reset|status|doctor|log|enable|disable` 控制。

### 四个实测踩坑（都写进 README 与 note）

1. **`drop-on-latency` + `queue leaky=downstream` 会雪崩**：源流一断就陷入 CRITICAL 报错风暴（96 万条/2 分钟）、CPU 73%、进程永不退出。三变体对照实测。
2. **`rtmpsink` 远端断开后 gst 不退出**（CLOSE-WAIT 但进程存活）→ 自写看门狗，检查到目标 `host:port` 的 TCP 是否 ESTAB + 发送队列积压。
3. **上游相机服务会静默整树消失**：`start_server.sh + push_video.sh` 全没（mediamtx 被 init 收养存活），源变 404，dmesg 有 `uvcvideo: Failed to resubmit video URB (-1)`。
4. **`mpph264enc` 喂 NV12 会花屏**（绿紫横向条纹）→ 逐级抓帧定位：硬解没问题，是 H.264 编码器 NV12 输入错位，**必须用 I420**。代价：`videoconvert` NV12→I420 在这颗 ARM 上要 99.5% 单核/路，多线程更慢，系统无 RGA 转换元素 → 两路合计约 2 核。

### 其他关键发现

- `basic_server`（`/opt/robot/share/basic_server/bin/`）会调用 `rtsp_service/restart.sh`，而该脚本含 `pgrep -f "gst-launch" | kill -9` —— 会无差别杀掉系统里所有 gst-launch（包括第三方转发器）。对策：把 gst-launch 复制成 `bin/rtmp-gst` 调用，argv[0] 不含该字符串。注意 **0 字节文件也满足 `-x`**，校验必须同时查 `-s`。
- **操作 196 时命令行不要含 `push_video` 或 `v4l2` 字样**，否则会被 `restart.sh`/`stop.sh` 的 `pkill -f` 连累杀掉自己的命令；这类操作要写进脚本文件再跑。
- 196 经 WiFi（`p2p0`，Tenda_FCFA20_5G）接入，链路会间歇性断（表现为 ARP 表里 196 消失、SSH 超时）。`ping 网关不通`不能作为判断依据（Tenda 屏蔽 ICMP）。
- 196 上端口 3000 = `node /home/tank/m20/server.js`（PM2 托管，机器狗自带 Web 控制台），占 1.2% CPU，与推流无关。
- 相机前后视映射（video1/video2 ↔ m20pro-f/b）**尚未物理核实**，config.env 里可一行对调。

### 性能占用实测对比（m20video vs 196 端口3000 服务 vs 120 中继）

采样：内核 cgroup `cpuacct.usage` 增量 + `/proc/PID/stat` 增量，窗口 20s，8 核整机。

| 服务 | CPU(%单核) | 折合核数 | 内存RSS | 进程/线程 |
|---|---|---|---|---|
| m20video 两路（H.265→H.264 转码） | **197.6%** | **1.98 核** | 29.9 MB | 9 / 37 |
| 3000 端口（`node /home/tank/m20/server.js` + PM2） | **5.4%** | 0.05 核 | **283 MB** | 2 / 204 |
| 120 中继（单路纯 remux 参照） | 12.8% | 0.13 核 | 22.3 MB | — |

- 系统总线 CPU：19.2%（仅 3000 服务）→ 43.7%（+m20video），约 +24.5 个百分点。
- **CPU 上 m20video 是 3000 服务的约 37 倍；内存上 3000 服务是 m20video 的约 9.5 倍**（283MB / 204 线程，典型 Node+PM2 形态）。
- 120 纯 remux 单路仅 0.13 核，196 转码单路 0.99 核，**约 7.6 倍差距**，全部来自 `videoconvert` 的 NV12→I420。
- 结论：把相机改 `mpph264enc` 让中继退回 remux，预期 1.98 核 → 约 0.26 核，比"关掉服务"收益更大。

## 4. M20 GPS 获取方式

**结论：能获取。GPS 模块与串口完全正常，但当时无定位解 —— 室内只搜到 1 颗北斗。**

数据链路：`GPS 模块 ──/dev/ttyS5 @115200 (NMEA)──> gps_node ──> DDS 话题`

实测证据：原始 NMEA `$GNGGA,...,0,00,...` 定位质量=0；`$GPGSV,1,1,0` GPS 0 颗；`$GBGSV,1,1,1,38,,,24` 北斗 1 颗（信噪比 24）。
`gps_node` PID 3087，`taskset -c 1,2,3`，持有 `/dev/ttyS5`；启动脚本 `/opt/robot/share/node_driver/scripts/gps_run.sh`；配置 `config/gps.yaml`。

四条获取途径：

- **A. ROS 2 话题（推荐）**：`/GPS`(`drdds/msg/NavSat`)、`/GPS_SYS_MODE`、`/GPS_CFGSYS`、`/GPS_SYN_UTC`，各 1 发布者。**发布者节点名是 `_CREATED_BY_BARE_DDS_APP_`（裸 DDS，不走 rmw）**；`drdds` 消息 Python 侧可 import。⚠️ 无定位时 `ros2 topic echo` 无任何输出（不是报错）。Foxy 不支持 `--once`。
- **B. M20 直连协议**：`basic_server` 监听 TCP 30001 / UDP 30000，报文 `Items.GPS`。机器狗 Web 控制台用它取 GPS，并按 `config.json` **每 1400ms 上报到 `http://10.21.31.150:3000/api/gps/data`** —— 该上报由已停用的 3000 服务执行，**当时已没有在上报**。
- **C. 直读串口 NMEA**：需先停 gps_node 才能独占（不推荐）。
- **D. 看解析结果**：`m20gps`。

**RTK**：`/FIBOCOM/net_rtk/gngga` 与 `/FIBOCOM/net_rtk/heading` 均为 **0 发布者**，RTK 未激活。相关模块 `/opt/robot/share/gs2dds/`。

交付：`m20gps` 命令（`/usr/local/bin/m20gps`，源码 `../project/rtmp_1012/patch/m20gps`），子命令 `status|watch|nmea|topic|log`，含定位质量判读与 ROS 话题发布者数。

## 5. M20 直连协议完整逆向 + GPS 双源确认

用户追问"目前是否拿不到经纬度"→ 答案是"拿不到，但不是故障，是没定位"，并补做第二数据源验证。

**M20 直连协议（TCP 30001 / UDP 30000，服务端 `basic_server`）已从 `/home/tank/m20/server.js` 完整逆向并实测打通**：

- 帧：`[EB 91 EB 90] + 长度(UInt16LE) + 序号(UInt16LE) + 格式(UInt8=1) + 7字节保留 + UTF-8 JSON`
- **`HEADER_LEN = 16`**（⚠️ 关键坑：`server.js` 里是变量，按可见字段先推成 9，服务端从错位取 JSON 回 `JSON format parsing failed,error code:57346`；最终从服务端返回的原始字节量出真实头长 16）
- 载荷：`{"PatrolDevice":{"Type":T,"Command":C,"Time":"YYYY-MM-DD HH:MM:SS","Items":{...}}}`
- 心跳：`Type=100, Command=100, Items={}`，每 800ms 一次
- 上报遥测：`(100,100)`ErrorCode / `(1002,3)`ErrorList / `(1002,4)`MotionStatus+MotorStatus / **`(1002,5)`BatteryList+BatteryStatus+DeviceTemperature+Led+GPS+DevEnable+CPU** / `(1002,6)`BasicStatus / `(1002,7)`NavStatus+LocationStatus
- `Items.GPS` 字段：Latitude Longitude Altitude Speed Course FixQuality NumSatellites VisibleSatellites HDOP VDOP PDOP

**GPS 双源对照（结论一致）**：本机模块 `/dev/ttyS5`→gps_node 与狗端 M20 协议 `(1002,5).GPS` 均为 0.0/0.0、FixQuality 0、卫星 0/可见1。
→ **经纬度当时拿不到，唯一原因是搜不到足够卫星**（GPS 0 / GLO 0 / GAL 0 / 北斗 1 颗，信噪比 24；定位需 ≥4 颗）。挪到室外即可。
