# M20 Pro：ROS 2 导航与强化学习部署路线

## 1. 结论

主导航链路建议采用：

**ROS 2 Jazzy + Nav2 + MPPI（Omni）+ M20 `/NAV_CMD` 适配器**

Odin Nav Stack 暂不作为主部署方案，只保留其 NeuPAN、局部规划和工程组织方式作为参考。原因：

- Odin 主体是 Ubuntu 20.04 + ROS 1 Noetic；
- 默认绑定 Odin1 感知设备、Unitree Go2 控制器和特定 TF/话题；
- NeuPAN 当前不原生支持全向底盘，而 M20 的导航接口包含横向速度 `y_vel`；
- 迁移 Odin 需要同时修改控制器、感知输入、TF、模型尺寸及 ROS 1/ROS 2 通信，工作量大于直接采用 Nav2。

虽然 ROS 2 Lyrical 更新，但第一版真机系统建议选 Jazzy：生态成熟、维护周期长，且 NVIDIA Isaac ROS 已有明确支持。等硬件和全部依赖验证完，再评估升级 Lyrical。

## 2. 两条链路必须隔离

### A. 高层自主导航链路（优先）

```text
M20 传感器 / 内置状态
        │
        ├── 点云、深度、里程计、IMU、TF
        ▼
ROS 2 Jazzy 伴随计算机
        │
        ├── 定位 / 建图
        ├── Nav2 行为树与全局规划
        └── MPPI Omni 局部控制器
        ▼
标准 /cmd_vel
        │
        ├── 限速
        ├── 超时看门狗
        ├── 急停联锁
        └── Jazzy ↔ M20 Foxy/DDS 适配
        ▼
M20 /NAV_CMD
        ▼
机器人原厂底层运动控制
```

该链路不直接控制关节，不替换原厂步态控制器，适合作为第一阶段真机部署目标。

### B. 强化学习底层运动链路（后置）

```text
M20 URDF / MJCF / USD
        ▼
Isaac Lab + DeepRobotics rl_training
        ▼
训练、评估、Sim-to-Sim
        ▼
导出 ONNX 策略
        ▼
DeepRobotics sdk_deploy
        ▼
/JOINTS_CMD 等关节级接口
```

该链路会绕过或替换部分原厂底层能力，风险明显高于 `/NAV_CMD` 高层导航。只有在仿真测试、限幅、跌倒保护、吊装测试和 SDK 授权全部通过后才进入真机。

**禁止把 Nav2 的 `/cmd_vel` 直接接到 `/JOINTS_CMD`。**

## 3. 推荐组件

| 目标 | 首选 | 备选/条件 |
|---|---|---|
| ROS 2 发行版 | Jazzy | Lyrical：依赖全部兼容后再升级 |
| 导航框架 | Nav2 | Odin 仅作算法参考 |
| 局部控制 | MPPI，运动模型设为 Omni | Regulated Pure Pursuit 用作低速对照 |
| 2D 激光建图 | SLAM Toolbox | 已有稳定地图时只做定位 |
| RGB-D / 3D 激光通用建图 | RTAB-Map ROS 2 | 适合不依赖 NVIDIA GPU 的方案 |
| Jetson 高性能 3D 感知 | Isaac ROS nvblox | 需要受支持的 NVIDIA GPU 与传感器 |
| 激光里程计 | KISS-ICP | 只负责里程计时使用，不代替完整地图管理 |
| URDF/MJCF/USD | deep_robotics_model | 校准 M20 Pro 的传感器外参后派生 |
| 强化学习训练 | DeepRobotics rl_training | 基于 Isaac Lab |
| RL 真机部署 | DeepRobotics sdk_deploy | 需要匹配系统版本和 SDK 授权 |

## 4. 分阶段学习与部署

### 阶段 0：硬件与接口盘点（半天）

确认：

- 具体型号：M20、M20 Pro 或 M20S；
- 机器人系统版本；
- 伴随计算机型号、GPU、内存和 Ubuntu 版本；
- 是否实际拥有 Odin1；
- 可用的深度、点云、激光、IMU、里程计话题及频率；
- `base_link`、传感器坐标系、`odom`、`map` 的 TF 关系；
- `/NAV_CMD` 的消息类型、字段和原厂服务依赖；
- 急停、遥控接管和断连停车是否可用。

交付物：一份话题清单、一张 TF 树、一份硬件清单。

### 阶段 1：URDF 与接口认知（1–2 天）

1. 在 `deep_robotics_model` 中查看 M20 的 URDF、MJCF 和 USD。
2. 理清：
   - `base_link` 与足端关节树；
   - 碰撞模型和机器人外形；
   - 质量、惯量和关节限制；
   - 传感器相对机身的外参。
3. 为 Nav2 单独定义：
   - `base_footprint`；
   - 2D footprint/polygon；
   - 传感器 TF；
   - 最大纵向、横向和偏航速度。

验收：RViz 中模型、TF 和传感器数据方向一致，无跳变或镜像。

### 阶段 2：Nav2 仿真最小闭环（2–4 天）

1. 安装 ROS 2 Jazzy、Nav2 和仿真环境。
2. 使用 MPPI，运动模型设置为 Omni。
3. 先使用静态地图和模拟里程计验证：
   - 目标点下发；
   - 路径规划；
   - 障碍绕行；
   - 横向速度；
   - 恢复行为；
   - 取消目标后的停车。
4. 将 `/cmd_vel` 限制在保守范围。

验收：仿真连续运行 30 分钟，无控制发散、碰撞和取消目标后继续移动。

### 阶段 3：M20 导航适配器（2–3 天）

适配器职责：

- 输入标准 ROS 2 `/cmd_vel`；
- 转换为 M20 `/NAV_CMD` 的 `x_vel`、`y_vel`、`yaw_vel`；
- 处理 Jazzy 与机器人 Foxy/DDS 的通信差异；
- 限幅、加速度限制和命令平滑；
- 超过设定时间未收到新命令时发送零速度；
- 急停或遥控接管时立即停止发布；
- 输出诊断状态和最后一次命令时间。

开发顺序：

1. 只记录、不向机器人发送；
2. 架空或吊装状态下发送零速度；
3. 遥控待命，进行极低速单轴测试；
4. 再测试组合速度和导航闭环。

验收：断开导航节点、断网、取消目标、急停时均能在设定超时内归零。

### 阶段 4：定位与建图（3–7 天）

按传感器和算力选择：

- 只有 2D 激光：SLAM Toolbox；
- RGB-D 或普通 3D 激光：RTAB-Map ROS 2；
- Jetson + 受支持的深度相机/3D 激光：Isaac ROS nvblox；
- 需要独立激光里程计：KISS-ICP，再接入地图/定位组件。

第一轮先复用 M20 已有里程计和定位输出，避免同时调试底盘、SLAM 和导航。

验收：静止漂移、回环误差、走廊退化和高速转向下的定位稳定性满足场景需求。

### 阶段 5：真机导航（3–5 天）

1. 清空测试区，保留遥控接管人员。
2. 初始限速建议不高于：
   - 纵向：`0.10 m/s`
   - 横向：`0.08 m/s`
   - 偏航：`0.20 rad/s`
3. 依次测试直行、横移、转向、停车、避障和重规划。
4. 稳定后逐级提高速度，每次只改一类参数。
5. 暂停自动回充等会与 `/NAV_CMD` 冲突的原厂任务。

验收：100 次目标任务中无碰撞、失控、取消后移动或断连后持续运动。

### 阶段 6：强化学习（并行学习，真机后置，1–3 周）

1. 运行官方 M20 Isaac Lab 任务。
2. 学会观察量、动作、奖励、终止条件和域随机化。
3. 重复训练并在仿真中回放。
4. 导出 ONNX。
5. 通过 `sdk_deploy` 做 Sim-to-Sim。
6. 检查系统版本、SDK 授权、关节限幅和急停。
7. 吊装状态下做首次真机推理，再进入地面低速测试。

验收：策略在随机地形、扰动、传感器噪声和模型参数变化下仍稳定；仿真失败样例已经被纳入训练或保护逻辑。

## 5. 已准备的本地资料

```text
M20-pro/
├── deep_robotics_model/   # M20 URDF / MJCF / USD
├── rl_training/           # Isaac Lab 强化学习训练
├── sdk_deploy/            # M20 ROS 2 Sim-to-Sim / Sim-to-Real
└── Odin-Nav-Stack/        # ROS 1 Odin，作为参考
```

当前 Windows 工作区适合阅读、配置和开发文档；ROS 2、Isaac Lab、Nav2 与真机部署应在 Ubuntu 伴随计算机或独立 Linux 工作站上执行。

## 6. 下一次现场采集

在机器人和伴随计算机上采集：

```bash
ros2 topic list -t
ros2 node list
ros2 service list -t
ros2 param list
ros2 run tf2_tools view_frames
```

重点补充以下话题的类型、频率和一小段样例：

- 里程计；
- IMU；
- 深度图、点云或激光；
- `/NAV_CMD`；
- 机器人状态、急停和控制模式；
- TF。

拿到这些信息后，再生成精确的 Nav2 参数、话题重映射和 `/NAV_CMD` 适配器代码，避免猜测厂商消息定义。
